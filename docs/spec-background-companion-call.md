# 后台陪伴通话规格

> 状态：已完成产品决策，待拆票实现
> 日期：2026-08-24
> 第一版语音后端：VoxCPM2
> 相关决策：[ADR-0001](./adr/0001-background-companion-call-boundaries.md)
> 相关路线图：[实时语音](./roadmap-realtime-voice.md)、[共同体验陪伴](./roadmap-shared-experience-companion.md)、[Memory Brain](./roadmap-memory-brain.md)

## 1. 结论

新增独立的 **Background Companion Call（后台陪伴通话）**。它面向用户一边游戏、工作或阅读，一边长时间挂着桌宠、偶尔主动说几句话的场景。它不是普通实时通话主动性的第四档，也不是会观察屏幕和媒体内容的共同体验会话。

第一版以 VoxCPM2 为唯一交付和实机验收后端。用户默认按住键盘右侧 `Alt` 发言；空闲时不采集或上传麦克风 PCM。角色可以在确定性预算允许时低频主动开口，但必须服从分钟级静默、无人回应退场和用户显式静默。文本模型继续复用当前 DeepSeek 或本地 Ollama 配置；本特性不接入 CosyVoice、火山或其他在线语音 API。

本规格定义产品合同、状态模型、模块接口、私有协议、分阶段实现和验收门槛。它不宣称当前代码已经实现这些行为。

## 2. 目标与非目标

### 2.1 目标

- 陪伴会话可持续数小时，不要求用户维持连续对话。
- 用户不切换焦点即可通过全局按住说话可靠取得发言权。
- 用户松键后才提交终态 ASR；元元正在播放时支持可恢复的两阶段打断。
- 60 秒安全结束后允许把后续录音合并成同一个用户回合。
- 主动发言稀疏、可关闭、有硬预算，且一次无人回应后停止继续试探。
- 睡眠、锁屏和 VoxCPM2 中断不会补发过期主动话语，也不会悄悄丢掉可恢复会话。
- 只有用户真实说出的内容和实际播放完成的角色句段进入现有对话与 Memory 流程。

### 2.2 非目标

第一版不实现：

- 常开麦自由对话、唤醒词或声纹寻址；
- 耳机自由对话；
- 屏幕、前台应用、游戏画面、系统音频或环境媒体理解；
- 根据键鼠活动、游戏强度或系统勿扰自动推断用户是否忙碌；
- 在线语音 API 或非 VoxCPM2 的产品验收；
- 自动跨应用重启恢复正在进行的陪伴会话；
- 把主动候选、未回应、控制事件或外部观察写入 Memory。

## 3. 用户体验合同

### 3.1 独立入口与准备

- 聊天窗口提供独立的“开始陪伴”入口，不能藏在普通通话的主动性下拉框中。
- 启动后依次展示固定准备阶段，例如“正在准备语音”“正在准备听写”。VoxCPM2、ASR、文本后端和私有协议全部就绪后才进入“陪伴中”。
- 准备期间可以取消；半初始化会话不产生聊天消息或 Memory 写入。
- VoxCPM2 慢启动可超过现有 180 秒提示线，但 UI 必须持续显示仍在准备。
- 陪伴静默期间不卸载模型。结束陪伴、退出应用、切换人设、参考音、ASR 或文本后端时才释放或重建。
- 快捷键和“允许角色主动说话”可热更新；改变核心后端配置时进入暂停并要求重新准备。

### 3.2 按住说话

- 默认快捷键为物理 `RightAlt`；设置中可配置单键或组合键，并区分左右侧修饰键。
- 全局快捷键只观察，不拦截，按键仍传给游戏或当前应用。
- 只有陪伴会话处于可收听状态时快捷键才生效。自动重复只认第一次按下。
- 按下后 UI 立即进入“准备收听/正在听你说”状态；只有麦克风真正开始采集后才显示“正在听”。空闲时不保留采集中的麦克风流，也不上行 PCM。
- 松开后结束本段并执行终态 ASR。小于最低时长、过静或无有效文本的录音不形成用户回合。
- 胶囊同时提供鼠标按住说话按钮，语义与快捷键完全一致。
- 失焦、钩子重注册、设备断开、睡眠或丢失 `keyup` 时必须合成安全释放，不能留下永久录音态。

### 3.3 播放中的按住说话

- 按下时立即暂停 Worklet 消费和 VoxCPM2 后端发送，但不立刻清空回复、句段账本或可恢复音频。
- 有效用户回合确认后清除未播放音频、取消旧 generation，并从 Audible History 回答用户。
- 无效录音或取消则从候选点恢复原回复，不能生成新用户消息。
- 暂停期间所有队列继续服从现有上限；后端必须停止下发，不能让3秒ring成为长录音缓存。

### 3.4 60秒安全结束与续说

- 单个 Talk Hold 最长60秒。到达上限后自动结束采集，并在胶囊和完整通话界面显示强提示“本段已自动结束，可再次按住继续”。
- 自动结束后进入8秒 Continuation Window，暂不请求AI；UI显示倒计时和“立即发送”“取消”控制。
- 8秒内再次按住会扩展同一用户回合。最多3段、总采集时长最多180秒。
- 每段独立做终态ASR，按段序拼接有效文本；PCM只在有界内存中保留到该段ASR完成，随后立即释放，不落盘、不进日志。
- 第二或第三段若在60秒前正常松开，立即提交整个合并回合；只有再次达到60秒才开启新的8秒窗口。
- 达到3段、180秒或用户点击“立即发送”时直接提交；点击取消丢弃整个尚未提交的合并回合，并恢复被暂停的角色播放。
- 服务端逐段限制最多512个识别字符，合并回合最多1536字符。超限必须给固定可理解提示，不静默截断。实现时应同步扩大陪伴待回复恢复合同，不能让重连只保留前512字符。

### 3.5 主动说话

设置提供独立的“允许角色主动说话”开关，默认开启。关闭后不安排接通问候、追问或静默主动候选，但按住说话和角色应答保持可用。

开启时采用以下固定策略：

- 核心能力就绪后允许一次接通问候。
- 后续候选只能从最后一次有效用户互动或最后一次角色播放完成回执之后计时，至少静默20分钟。
- 使用滑动60分钟预算，每小时最多实际播放2次主动话语；预算是上限，不是目标。
- 睡眠、锁屏、恢复、生成、播放、Talk Hold、Continuation Window 和显式静默期间不累计合资格静默时间。
- 候选触发时若用户正在录音、ASR、回复、播放、恢复或未完成回执，候选直接失效；不排队稍后补说。
- 一次主动发言播放完成后开启5分钟回应窗口。若没有有效用户回合，会话进入无人回应的 Quiet Companionship，不再调度主动发言；下一次有效用户回合自动解除。
- 用户明确说“我先忙”“安静会儿”等进入显式 Quiet Companionship。它只能由明确的“继续聊”类回合或UI恢复控制解除，普通发言不隐式解除。
- 用户关闭主动开关立即取消所有未开始的候选和计时；已经开始播放的主动句允许用户用Talk Hold打断，关闭开关本身不伪造打断。

主动内容按以下优先级选择，找不到合适内容时保持安静：

1. 当前陪伴会话中尚未收束且适合轻触的用户话题；
2. 用户明确置顶的记忆或待办承诺；
3. 一句低负担状态关心；
4. 仅当Fresh Topics已开启时，从既有本地缓存选择最多一条低频话题。

禁止猜测用户正在做什么、假装看见屏幕或听懂游戏、主动重提敏感/医疗/财务/关系冲突/负面经历、为了耗尽额度强行开口，或把用户未回应解释为关系态度。

### 3.6 结束、暂停与恢复

- 会话没有固定时长，直到用户手动结束、退出应用或切换需要重建的核心配置。
- 系统睡眠和锁屏冻结所有计时并安全释放Talk Hold；唤醒后不补发错过的主动候选。
- VoxCPM2或本地传输中断后进入“恢复中”，采用有界退避恢复，最长5分钟。期间不采集语音、不累计主动静默时间。
- 恢复成功后继续当前会话和有界Audible History。未播草稿继续遵守现有丢弃规则。
- 5分钟失败后进入“陪伴已暂停”，保留会话上下文并提供“重试”“结束”；不能伪装仍在收听，也不能自动开启新会话。
- 文本、ASR或TTS的单轮可恢复失败只结束该轮，并允许下一次Talk Hold重试；配置失效、不可恢复协议错误和用户退出才结束会话。
- App重启不自动恢复进行中的陪伴会话。

## 4. 状态模型

不要创建一个包含所有组合的巨型状态枚举。策略模块维护三个正交状态轴，并从组合状态导出UI：

```ts
type CompanionState = {
  lifecycle:
    | "stopped"
    | "preparing"
    | "active"
    | "recovering"
    | "paused"
    | "ending";
  input:
    | "idle"
    | "acquiring-mic"
    | "capturing"
    | "transcribing"
    | "continuation-window"
    | "committing";
  initiative:
    | "disabled"
    | "eligible"
    | "awaiting-response"
    | "quiet-unanswered"
    | "quiet-explicit";
};
```

所有时长使用注入的单调时钟。策略只保存deadline和有界计数，不把wall clock、计时器句柄、文本、PCM或模型对象放进状态。睡眠/恢复通过显式事件冻结并重算deadline；不得用“唤醒后发现超时”触发补发。

关键不变量：

- `lifecycle !== active` 时不能开始采集或主动生成；
- 同时最多一个Talk Hold、一个ASR任务和一个待提交用户回合；
- `input !== idle` 时不触发主动候选；
- `initiative !== eligible` 时不安排主动计时；
- 任何旧session、shortcut revision、turn、segment、generation或timer事件都不能改变新状态；
- 用户回合只有在有效文本已合并并显式commit后存在；
- 角色历史只有播放完成回执能够推进。

## 5. 模块与接口

### 5.1 `CompanionSessionPolicy`

新增纯策略模块，例如 `src/ai/companion-session.js`。它是陪伴行为的主要测试seam：

```ts
type CompanionDecision = {
  state: CompanionState;
  actions: CompanionAction[];
};

reduceCompanionEvent(state, event, monotonicNowMs): CompanionDecision;
```

事件只含固定枚举、数字身份、布尔结果和必要的分类结果；不把DOM、WebSocket、Tauri `invoke`、原始文本或PCM交给策略。动作包括准备/停止采集、暂停/恢复/清空播放、开启/取消deadline、提交/取消回合、请求主动候选、进入恢复或更新UI。复杂规则集中在该模块，调用方不重复实现计时与静默语义。

### 5.2 原生快捷键适配器

新增Rust模块管理陪伴Talk Hold，而不是继续扩张 `lib.rs`：

- 复用 `tauri-plugin-global-shortcut` 的 `ShortcutState::Pressed/Released`；
- 注册记录带单调`shortcutRevision`，迟到事件必须被前端拒绝；
- 持久化规范化物理键和修饰键，区分左右侧；
- 拒绝与现有聊天快捷键、已注册快捷键和禁止组合冲突的保存；
- Windows优先识别`AltGr`语义并fail closed。无法可靠区分的布局在设置测试区显示兼容性警告，要求换键；
- 设置页“按下以测试”只显示识别结果，不发送Talk Hold事件；
- 事件观察而不抑制当前应用按键。

这里存在真实平台风险：必须在macOS与Windows验证插件是否能稳定保留左右`Alt`和`AltGr`语义。若插件抽象丢失侧别，应先建立窄的原生适配器或更换快捷键实现，不能把左右`Alt`偷偷归一化。

### 5.3 VoxCPM2传输适配器

普通实时会话不得因新特性改变。陪伴会话只在双方显式协商后启用项目私有的`push-to-talk-v1`：

```json
// start offer
{"inputMode":["push-to-talk-v1"]}

// session selection
{"inputMode":"push-to-talk-v1"}
```

建议的有界控制合同：

- `talk_hold_start { turnId, segmentId }`
- 原有16k mono PCM binary，仅在打开的segment内接受
- `talk_hold_end { turnId, segmentId, reason: "released" | "safety-limit" }`
- `talk_segment_result { turnId, segmentId, state, chars }`，正文继续复用现有ASR事件，不进诊断
- `talk_turn_commit { turnId, segmentIds }`
- `talk_turn_cancel { turnId, reason }`

Python服务独立验证严格顺序、单segment、60秒/512字符、最多3段、总180秒/1536字符以及一次commit。未知、重复、越界、过期或未协商控制帧fail closed。PCM仍不落盘；ASR admission保持1，最多3段PCM排队且总时长有硬上限。每段ASR完成立即释放PCM。

逐段ASR正文只更新同一个未提交用户草稿；前端按`turnId + segmentId`严格排序展示，Python保留有界清洗结果供最终commit。任何segment结果都不能单独进入history、recap、Memory或触发LLM。只有`talk_turn_commit`成功后才发布一次合并后的final ASR和一个用户回合。

Talk Hold开始时服务端必须暂停当前provider sender，效果等价于现有candidate的可恢复让声，但不能伪造Speech Candidate。有效commit才确认打断和请求LLM；无效或cancel恢复播放。`managed-v1`、generation、segment receipt、CancelScope、`provider-pcm-v1`和Audible History继续作为下行权威，不另造第二套播放协议。

### 5.4 UI适配器

胶囊保持稳定尺寸，不因文案变化跳动。至少表达：准备中、陪伴中、正在听、正在转写、可继续说、自动结束强提示、元元说话、恢复中、已暂停、安静陪伴和错误。紧凑态必须始终提供结束、鼠标按住说话和当前主动性状态；完整态额外提供立即发送、取消、恢复主动、重试等控制。

设置新增：

- 陪伴模式默认Talk Hold快捷键；
- 快捷键录入/测试/冲突或AltGr提示；
- “允许角色主动说话”，默认开启；
- 当前只支持VoxCPM2的明确说明。

不可只用颜色传达录音、自动结束、恢复或安静状态；按钮和状态文字需要可访问名称。

## 6. 数据、Memory与诊断

- 合并后的用户文本作为一条用户消息；最多3段的边界不应暴露成3个虚构回合。
- 角色只有实际播放完成的连续句段进入Audible History、聊天recap和后续Memory提取。
- 用户真实回应主动问候后按普通对话处理。
- 主动问候/Fresh Topic正文、未回应、快捷键事件、误触、自动结束、续说倒计时、恢复/暂停控制不进入Memory。
- 陪伴模式不改变persona/system/skill权威；Fresh Topic继续是不可信、短期、有界观察，不进入Memory。
- 诊断可新增固定schema版本、协商能力、Talk Hold数量、自动结束/继续/取消计数、segment时长桶、主动候选/播放/无人回应/静默计数、恢复耗时和结果。
- 诊断禁止按键原值、用户/角色文本、ASR正文、PCM、persona、Memory正文、话题、路径、设备名、wall clock和raw error。

## 7. 分阶段实现

每个阶段按 `docs/testing-development-loop.md` 执行Red -> Green，并先定义公开seam下的行为测试。

### M0：纯策略与设置合同

- 实现三个正交状态轴、单调deadline和动作输出；
- 增加陪伴设置归一化、默认主动开启、RightAlt配置schema；
- 覆盖20分钟、2次/滑动小时、5分钟无人回应、显式/隐式Quiet Companionship、睡眠冻结和迟到事件；
- 不接UI、不启动麦克风。

### M1：独立入口与VoxCPM2准备

- 增加独立入口、胶囊状态和VoxCPM2-only能力门；
- 完成准备、取消、慢启动、配置热更新、结束清理；
- 旧服务未协商`push-to-talk-v1`时显示不支持，不能降级为常开麦。

### M2：单段Talk Hold竖切

- 原生Pressed/Released -> 前端策略 -> WebView采集 -> Python ASR -> LLM/TTS -> Worklet回执端到端贯通；
- 覆盖普通发言、过短/过静/空ASR、播放中有效打断、误触恢复、鼠标控制、丢失release和取消；
- 空闲状态验证无mic track、无PCM上行。

### M3：60秒安全阀与合并回合

- 加入强提示、8秒窗口、立即发送/取消、3段/180秒/1536字符合同；
- 覆盖第59.9/60秒、窗口前后按键、第二段短松键、第三段达到上限、ASR慢于下一次采集、断线与迟到segment结果；
- 恢复合同必须保留完整待回复合并回合。

### M4：低频主动性

- 接入接通问候、20分钟deadline、滑动小时预算、候选优先级和播放回执；
- 接入主动开关、无人回应与显式Quiet Companionship；
- 复用现有Memory/Fresh Topic有界查询，不把观察正文写入诊断或Memory；
- 不接屏幕、系统音频、键鼠忙碌推断。

### M5：五分钟恢复与长会话

- 扩展VoxCPM2恢复为最长5分钟退避，增加paused/retry语义；
- 接入系统睡眠/唤醒/锁屏可获得的原生事件，冻结策略时钟；
- 验证旧session、shortcut、timer、turn、segment和generation事件均不能污染恢复后的会话。

### M6：真实设备验收后发布

- macOS与Windows分别进行至少4小时挂机；
- 验证RightAlt、AltGr/非AltGr布局、改键、游戏全屏、工作应用、睡眠唤醒、VoxCPM2进程故障和模型慢启动；
- 达到第8节门槛前保持实验入口，不改变普通实时通话默认行为。

## 8. 验收场景与门槛

### 8.1 自动化行为场景

| 类别 | 必须覆盖 |
| --- | --- |

### 8.2 实机门槛

macOS和Windows各自必须记录实际执行结果，不能互相代替：

- 4小时会话不发生无界内存/队列增长、孤儿进程、永久录音态或无法结束；
- 100次按下/松开均成对，key repeat不重复开段，丢失release在60秒内安全结束；
- idle期间系统麦克风采集与上行PCM均为零；
- 有效Talk Hold不会丢首个可理解词；按下到“正在听”P95目标不高于250ms，达不到时不得隐藏准备状态；
- 播放中误触可恢复，有效回合只提交一次，旧generation不继续出声；
- 20分钟、5分钟、每小时预算在系统睡眠前后不提前、不补发；
- 强制VoxCPM2退出后能恢复或在5分钟后进入可重试暂停态；
- Windows测试至少覆盖一种使用AltGr的布局和一种普通布局；无法可靠区分时验证fail closed及改键流程；
- 游戏或高负载工作场景记录CPU、GPU/统一内存、模型显存、首音频延迟和明显帧率影响，不先设无证据的性能承诺。

## 9. 开放问题与后续方向

以下问题不阻塞第一版，但不能被描述为已经解决：

1. WebView每次按下才获取麦克风能否稳定达到250ms且不丢首词；若不行，应评估窄的原生采集适配器，不能退回空闲常开麦而不重新决策。
2. Tauri全局快捷键插件在各平台是否保留物理左右侧与可靠AltGr语义；原型结果可能要求更换原生hook实现。
3. 180秒合并回合对Whisper/VoxCPM2共享资源、Memory提取和断线恢复的实际压力。
4. 耳机自由对话是否值得作为显式后续能力；它需要新的声学验收，不能由`push-to-talk-v1`自动推导。
5. 共同体验会话未来可向陪伴策略提供已授权、会话级的结构化事件，但需要独立能力协商、预算和隐私设计。

## 10. 完成定义

只有在M0--M6的自动化门禁和两平台实机验收均有记录后，第一版才可从“实验”改为可交付。静态审查、构建成功、单次短通话或只在一个平台运行都不构成完成。
