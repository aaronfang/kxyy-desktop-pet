# QQ 自然互动诊断、大肥鱼工程复核与合入优先级

日期：2026-10-30。范围：运行状态与源码调查、第三方一手源码比较、后续实施计划。本文不是功能完成声明；本轮未修改产品配置或发送 QQ 测试消息，未提交、未推送。

## 1. 结论

当前“一问一答、看不到主动消息”有两个直接原因，以及一个实现范围上的缺口：

1. **保存的 QQ 配置没有启用主动交流。** 用户选择的“自然”未体现在持久配置中；界面选中值与真正生效值之间缺少明确反馈。
2. **当前是语音回复模式，设计上仍为单条语音。** 已实现的最多三段发送只适用于普通纯文字回复；语音、表情组合及主动消息均不拆分。
3. **上一版加入的是保守的闲置联系机制，没有完整加入聊天节奏。** “自然”要求闲置 45 分钟，每次主人输入都会重置计时，因此连续聊天不会触发它。旧桌宠随机续说又被统一调度器关闭，所以没有替代的短时接话机制。

大肥鱼相关工程也没有一个可直接照搬的“真人感开关”。值得组合的是 Aurabot 的输入合并与表达动作、dafeiyu-astrbot 的真实活动与持续小目标、Bili Whale 的选题与反馈、speak-up 的可解释调度。短时自主续话仍需结合本项目独立设计和验收。

### 2.2 已实现的规则为什么不符合这次体验

| 当前实现 | 对体验的影响 | 源码 |
|---|---|---|
| 自然：闲置 45 分钟、间隔 3 小时、最多 3 次/日 | 不是聊天中十几秒后再想到一句；持续聊天会不断推迟资格时间 | [proactive.rs](../src-tauri/src/proactive.rs#L124) |
| 主人输入更新 `last_activity` | 即使启用自然，12:24:58 的输入也要到 13:09:58 才满足闲置条件，其余门禁还需通过 | [activity](../src-tauri/src/proactive.rs#L78) |
| 更主动：闲置 20 分钟、间隔 90 分钟、最多 5 次/日 | 改档位只改变长时间联系频率，不能补上短时续话 | [can_send](../src-tauri/src/proactive.rs#L104) |
| 旧闲置/随机续说被 `coordinatedQqInitiative=true` 关闭 | 避免双调度是合理的，但替代实现没有覆盖旧机制的全部行为 | [chat.js](../src/chat.js#L4973)、[旧续说门禁](../src/chat.js#L2668) |
| 多段发送条件为非主动、文字模式、无附件 | 当前语音模式无多气泡；主动消息即使文字也仍单条 | [qq.rs](../src-tauri/src/qq.rs#L1553) |
| 语音提示要求简洁口语；主动候选最多一句关心加一句展开 | 内容层也偏向短答，没有表达动作与后续回合计划 | [QQ 提示组装](../src/chat.js#L5001)、[主动决策](../src/chat.js#L5067) |
| 发送前持久化预算与未回应次数 | 失败/未知尝试也占预算；后续应区分“防重复预留”和“真实未回应” | [take_initiative](../src-tauri/src/qq.rs#L1223) |

这里必须区分：**一轮回复分三条发送**仍是一次生成；**自主续话**是在没有新用户问题时，基于前文再决定说一句；**长时主动联系**则是隔一段时间重新找主人。这三者目前仅实现了第一项的文字版本与第三项的保守基础。

### 2.3 候选来源的次要限制

当前记忆分档有 857 条经历，其中 72 条 `occurred_at` 在近三天；48 条待兑现约定，没有落在当前到期后两天有效窗口中的条目。最近 30 条经历事件缺少新格式 temporal 证据。这里不能把 `occurred_at` 或整理时间直接当作主人发言时间。

当前主动选题要求经历有可信 `temporal.messageAt`，或约定已到期且仍有效；因此不少旧经历不会入选。这是为防止串时间保留的边界，**不建议通过猜日期来扩大候选**。现有通用主动召回还先限为 3 项/300 字，之后才做调度候选过滤，存在被不合格条目占满的风险；本次没有复现该风险造成发送失败。

同时，本地兴趣缓存有 106 条资料，最近抓取于今天 11:29:48，电影、游戏、科技、音乐等感兴趣分类有内容，处于六小时有效期。所以不能笼统断言“没有任何来源”。当前关闭状态已经足以解释没发，来源限制是启用后还应解决的后续问题。

源码：[候选选择](../src-tauri/src/qq.rs#L1200)、[主动召回限制](../src-tauri/src/memory.rs#L3389)。

### 3.1 Aurabot：先改善正在聊天时的节奏

- 私聊默认等待 2.5 秒，最长 8 秒；期间新输入重置短等待，合并用户连发的短消息。生成中还尝试 steer。这能减少抢答，但当前项目应先实现有界合并与取消，不直接假定现有模型支持 steer。
- 一次输出支持文字、语音、贴纸、图片、引用等动作；文字气泡最多五个，按字数计算约 0.7–4.5 秒的间隔并加扰动。核心是有意义的表达单元，不是随机将句子切碎。
- 长时主动仍然保守：默认对象为空闲 40 分钟后有资格，间隔 60–180 分钟、每天最多四次、8–23 点。它不能证明缩短静默时间就能获得自然多轮。
- 允许 `[沉默]` 值得保留；允许“编也行”的日常经历与未答问题追加催问不建议引入。规则 mood 可以调节语气，但不代表真实情绪识别，也不应惩罚用户不回应。

### 3.2 dafeiyu-astrbot：真实“有事想到你”

2026-10-30 最新文档写明生活决策 v0.1 和主动联系协调 v0.1 已完成、云端已开启，但真实 QQ 联动 smoke 待做。研究方法 v0.4 有代码但默认关闭、未部署；虚拟房间、语义话题去重、统一 token 预算仍是后续工作。相较旧版调研，不能再一概归为规划，也不能提前算成全部实机完成。

- 从持续目标、作品、兴趣与近期真实决策中挑下一步，避免重复失败内容；进展需要 next_step、checkpoint 或新内容证据，换时间戳不算进展。无合格事项就休息。
- `df_share_thought` 从实际读到的内容产生具体感想，有意义才找主人；自己的感想不写成主人偏好，不编造视频剧情。截图也有当前 scope/run 与时效检查。
- 生活感想、作品、审批和定时主动共享联系额度。预留、派发、已送、未知、取消分别记录；未知结果不自动补发，TTS 或分段中主人发消息则在后续检查点停止。
- 默认预算和实际部署不同：默认三次/日、90 分钟冷却；文档中的云端配置仅一次/日、120 分钟冷却。真人感主要来自内容与连续性，并非高频发言。
- 人格约定对吃饭睡觉提醒一次、收到回应翻篇、晚安自然结束，这比所有消息统一重置一个静默计时器更符合语义。

### 3.3 AstrBot 主动插件：有用的管线，但仍是定时联系

配置默认随机间隔 30–600 分钟，1–7 点免打扰，最多四次未回应；启动主动默认关闭。持久任务恢复、过期检查和主人回复后重置状态值得参考。分段默认关闭，TTS 与额外文字默认开启，和本项目语音独占偏好不同。

不应照搬其将主动提示作为 user/assistant 对写入历史的做法，也不应照搬把沉默表现为失落催促的默认文案。发送异常后若结果未知，不能换另一条管线重发以免重复。

### 3.4 Bili Whale：先有真实活动，再有分享理由

在作息窗口内持久安排唤醒时刻，有最小间隔，也允许这次不看内容。实际流程是读取近期记录、浅读一组内容、挑少数深入、评分，只考虑分享排名第一且理由充分的内容。默认分享门槛为 13/20，理由至少八字。

用户真实点赞/回复才计作反馈；连续数天没有反馈时逐渐降低分享量，最终停止分享。这里的停止分享并不等于所有通知通道都停止，不能直接当作完整免打扰实现。它还有非分享自主写入不受每日上限的路径，本项目应另外设工具与 token 总预算。

可借鉴“资料→感想→选择性分享”和真实反馈衰减；首版直接复用已有授权的文字话题缓存，不引入视频解析。角色活动必须单独记录，外部原文继续遵守不进入用户 Memory 的现有约束。

### 3.5 speak-up：知道为什么这次没有说话

默认演练模式、每 30 分钟检查，按峰谷时段、距角色上次发言时间和连续未命中次数改变概率；忙碌/归档会话不打扰，主动后另设冷却。它复用已有 agent 会话，拥有约 60 条有界决策日志，可说明开关、静默、忙碌、冷却与概率未中等原因。

值得直接借鉴的是演练和解释能力，而不是再叠一个随机计时器。其宿主限制使唤醒通过带 source 标记的 user 消息实现；本项目已有原生主动事件，不应退回伪造主人发言。

## 4. 更有真人感的互动形式与优先级

以下是待实现方案，示例均为假设对话，不是读取到的用户历史。成本为相对工程量。

| 优先级 | 互动形式 | 示例与体验 | 合入方式/成本 |
|---|---|---|---|
| P0 | 生效设置与“为何没说话” | 显示“自然已生效；正在等当前回复结束”，不只显示 QQ 已连接 | 合并保存语义、草稿状态、固定原因与下次资格时间；小至中 |
| P1 | 接住连续输入 | 主人连发“今天好累”“开了四个会”“还没吃饭”，角色整体回应而非逐条抢答 | 有界输入合并、保留全部消息源时间与 id；中 |
| P1 | 一次表达有多个动作 | “四个会也太能耗人了。”→“先垫点东西吧，今天别再给自己加任务了。” | 每轮可选 1–3 个语义段；新输入取消尾部；中 |
| P1 | 同话题短时续话 | 角色讲到一半；主人说“嗯，你继续”；角色继续展开，偶尔再补一个真正的新想法 | 语义状态与续话许可，和长时日预算分开；中至大 |
| P1 | 知道什么时候等和结束 | “你选哪一个？”应等回答；“晚安”就结束；“哈哈”有时接梗，不一律当结束 | 会话短期状态，减少每次结尾反问；中 |
| P2 | 有由头的约定跟进 | 对“明天面试”在合适时间询问进展，而非当作已面试完成 | 事件时间、待跟进项、到时一次、回应后关闭；中至大 |
| P2 | 真实兴趣与持续小目标 | 实际看到授权资料后：“这条游戏消息让我想到你上次说的那个点……” | 独立角色活动记录、来源/进展、选择性分享；大 |
| P2 | 对不回应温和退避 | 无需回复的分享不等于连续催问；“今天忙”暂缓到指定时间 | 区分分享/提问/明确提醒，按真实互动反馈调整；中 |
| P3 | 更丰富的共同活动 | 一起讨论作品、轻量游戏或可选多媒体表达 | 依赖额外工具与偏好；视频仍后置，避免本轮扩张 |

最先影响用户体感的是 P1，而不是将 45 分钟改成 5 分钟。也不推荐每次强制三段、每句必问、随机停顿模拟思考，或编造“我刚出去吃了饭”。表达变化必须有语义理由。

### 4.1 语音模式的明确边界

当前用户偏好为“语音或独立表情”，不同时混发。文字多段已经有底层回执，可以先完善；语音增加多条消息则需作为独立偏好，不能暗中启用混合模式。

短时自主续话可以仍然发语音，但必须先解决：上一条是否已发送、音频时长、新消息取消、TTS 未完成作废。**QQ 回执只说明送达，不知道用户是否听完**，不得把收到回执当作通话播放完成。初版语音只考虑一条简短续话，文字可有 1–3 段；默认参数须通过实测确定。

## 5. 适合当前项目的实现结构

不引入完整 DSH/AstrBot 宿主。继续让 Rust 负责主人身份、配置、scope/lease、调度与送达，JS 复用人格、时间、记忆和模型调用。

1. **输入层**：短窗口合并真实消息，硬上限防止无限等待；原始 id、来源时间、语音转写/图片证据分别保留。不能用当前防抖式丢弃替代合并。
2. **会话节奏层**：仅保存有界短期状态，如 `展开中/等主人回答/可补充/收尾/暂忙`。模型可提出表达段和续话意图，原生策略最终准入。不能因一个“嗯”永久授权自行聊天。
3. **表达层**：一次回复 1–3 个完整段落，避免机械切句。后续消息和任何续话都能被新主人输入、切人格、关闭 QQ 或 lease 变化取消。未知发送不自动重发。
4. **三类时机分开**：当前回复的表达段、同话题短时续话、长时重新联系。短时可从约 8–25 秒的候选窗口开始实验，最多一次有新内容的补充；这些是待验证参数，不是成熟最佳值。明确等答案、晚安、忙碌和话题结束时不排续话。
5. **候选与预算**：回复内段落不各占一次日联系预算；短时续话另有会话上限；长时分享继续共用联系预算。预留、成功、未知与取消分开，只有真正发出的提问才影响对应未回应状态；未知保留防重复锁，不能通过释放预算导致重发。
6. **真实活动与记忆分离**：先用已授权缓存和用户明确任务。角色活动记录有来源时间、实际阅读范围、感想和下一步，不将角色观点写成主人事实。网页内容仍不得写入用户 Memory；已确认送达的真实对话按现有来源约束整理，取消尾部与内部控制事件不整理。
7. **可解释状态**：固定枚举和有界计数显示关闭、未保存、忙碌、静默、等待答案、缺少候选、模型建议等待、失败/未知、已发等。只记录状态与时间，不记录聊天/记忆正文、URL、令牌或音频。

实际作息可调整“何时值得联系”的权重，但明确的夜间免打扰、用户暂停与关闭服务仍是硬边界。显式预约提醒与可选社交分享也应分开，不能因为两次闲聊未回就吞掉用户要求的提醒。

## 6. 建议实施批次与验收

### 批次 A：先解决“选了却没生效”和不可解释

- 统一全局/QQ 保存的用户语义；成功提示必须能区分部分失败。主动控件显示草稿或已生效，不自动覆盖用户未保存字段。
- 增加固定原因诊断与演练候选，不向 QQ 实际发送。
- 回归：选自然→常用保存入口→原生实际状态和重启后均一致；失败时不显示全成功；所有决策拒绝路径可解释，日志无私人内容。

### 批次 B：会话状态、文字表达与短时续话

- 先做输入合并和有意义的 1–3 段；再加入同话题一次续话，与长时联系分开。
- 控制时钟覆盖：连发合并、明确等答案、轻回应、晚安、暂忙、插话、取消、重启不补发过期续话。
- 验证部分成功与迟到回执：只将确认前缀放入后续上下文和允许的记忆；未知不重复。
- macOS 真实 QQ 验收文字与当前语音模式，窗口隐藏也能工作；Windows/Linux 未执行必须明示。

### 批次 C：语音节奏与语义退避

- 在保留语音/表情互斥前提下测试单次短续话，按语音时长保守排时，主人新输入立即取消未发内容。
- 失败或未知不算“用户不理我”；无须回复的资料分享与问句分别处理。不能推断已读、正在输入或听完。
- 不改变已通过验收的电话播放回执与打断规则。

### 批次 D：真实活动、约定跟进与持续小目标

- 优先使用现有缓存与可信事件，建立角色活动独立记录；先一个兴趣、一个有界目标、一次分享，限制模型/工具预算。
- 真实资料、语义关联和进展均不足时允许休息；不补编生活，不重复分享同一来源。
- 用跨日情景验证：昨天事件不当成今天、未完成计划不当成事实、主人回应后关闭跟进、旧记忆未知日期不猜测。

各行为批次依照项目 Red→Green 与 `test:gate`，原生生命周期/QQ/音频还需真实应用端到端验收。自然度另需本人试用：观察接梗、打断、收尾与过度联系，不用“发出次数越多”作成功指标。可人工选取少量自愿提供的样例评价，不自动导出私人聊天。
