# QQ 语音消息与电话实施计划

日期：2026-10-27。关联[可行性调查](research-qq-voice-and-calls-2026-10-27.md)。本轮保留现有修改，不提交、不推送。Goal 已建立，完成标准包含真实媒体链路与记忆证据，不能以接口存在代替可用。

## 顺序与验收

1. **语音回复**：设置新增文字/语音回复选择，默认文字以保持兼容。语音复用桌宠当前 TTS 配置，不在电脑扬声器播放。由 Rust 生成有界临时音频、NapCat 转码并发送独立 record 消息。短期上下文和长期记忆仅在匹配的发送成功 ACK 后更新；未知投递不自动重发。合成或确定转码失败可文字回退；取消、关闭服务、换人格/昵称或删除记忆后不得发送旧任务。测试覆盖配置往返、真实 WS record 合同、超时/失败与清理。
2. **用户语音输入**：设置单独开启，明确提示使用 QQ 的云端语音转文字。只接受绑定主人的好友私聊、正确小号、新鲜且唯一的纯 record 事件；不读取事件附带的任意 URL/文件路径。通过 fetch_ptt_text(message_id) 取得有界完整转写，交给原有 QQ 人格、检索、显式保存与普通巩固流程。转写失败提示状态且不伪造文本、不写记忆；重连、设置改变、迟到响应不进入下一轮。验证重复/外人/群聊/混合媒体/空转写、取消恢复。
3. **原生 QQ 电话**：独立实验开关，继续主人白名单和小号身份验证。以独立进程协议连接 KoishiRTC 原生 AVSDK 桥，不将 GPL 实现复制进 MIT 产品。先核验已安装 QQ/SDK 与上游审计 profile，再完成音频设备、回环隔离、控制鉴权与生命周期集成；复用本地 ASR/LLM/TTS，不通过电脑麦克风/扬声器假装远端音频。支持明确登录/驱动缺失提示、接听/拒绝/挂断、关闭时清理、重连时隔离旧 callId。Mac 原生桥上游未经实测，签名/TCC/虚拟音频是实际依赖；禁止把 UI 点击或模拟事件当作通话成功。
4. **记忆闭环**：语音消息的真实转写和 ACK 后回复复用现有 QQ 主人分档及不保存/敏感信息过滤。电话只整理 final ASR 和有实际完成播放证据的回复；partial、合成未播放、被打断未完成、未知投递及旧会话不写入。每个成功回合幂等入队，数据库失败不阻塞通话。设置热更新、删除/清空记忆必须同步使在途任务失效。

## 验证与交付

每个切片先增加失败行为测试并确认 Red，再实现 Green。公开边界选用设置 UI、配置序列化、OneBot WS、音频 HTTP 和现有 Memory 入口。阶段结束跑受影响集成测试，交付前跑 npm run test:gate。
