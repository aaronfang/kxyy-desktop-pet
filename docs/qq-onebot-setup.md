# QQ 主人私聊首版

采用与 Coopanion QQ world 相同的个人 QQ + NapCat / OneBot v11 路线。本项目首版只支持本机正向 WebSocket、指定主人的好友私聊纯文字，默认关闭。群聊、临时私聊、图片、语音、电话、游戏操控和自动好友申请不在本轮范围。

## 配置

1. 注册一个独立个人 QQ 号，使用该号登录你自行部署的 [NapCat](https://napneko.github.io/)，与你的主 QQ 号互加好友。
2. 在 NapCat 的网络配置中启用 **OneBot v11 WebSocket 服务端**（正向 WS），监听 `127.0.0.1`，例如端口 `3001`。配置非空 access token；不要使用反向 WS 或远程监听。
3. 在桌宠“人设”页设置并保存明确的昵称。QQ 绑定昵称使用同一昵称，才能读取同一份长期记忆。
4. 打开“QQ 接入”，填 `ws://127.0.0.1:3001`、机器人 QQ 号、主人主 QQ 号；点击“填入当前人设与昵称”，核对绑定。默认元元人设卡 ID 留空；自定义卡使用对应 ID。
5. 填入与 NapCat 相同的 access token，勾选启用，点击 **单独保存 QQ 设置**。底部通用保存按钮不保存 QQ 配置。刷新状态看到 OneBot 已连接后，从主人号发一条文字。

桌宠与 NapCat 都须保持运行；首次握手用 `get_login_info` 校验真实登录号。主号与机器人号必须不同。QQ 回复复用当前文字模型和人格；当前生效人设/昵称必须与绑定相同，切换后不匹配便不回复。模型/API 未配置不会生成回复，连接成功只代表 OneBot 通道可用。NapCat 的登录与桌宠设置各自独立，桌宠不管理登录二维码。

## 人格、历史与好友范围

QQ 使用桌宠当前选中的人设卡、文字模型和在线提示词模式（完整/抽象），另附纯文字私聊约束；QQ 小号昵称不决定角色身份。默认元元的人设卡 ID 为空。切换角色时，先在桌宠保存新人设与明确的主人昵称，再在“QQ 接入”点击“填入当前人设与昵称”并单独保存 QQ 设置。当前没有独立于桌宠的人格选择器。

QQ 短历史仅包含本次 QQ 会话中成功发送的问答，最多8条消息（约4轮），不会拉取 QQ 服务端旧记录，也不会复制桌面聊天记录。重启、断线、保存配置或记忆变更会清空短历史。读取长期记忆时只召回绑定人设和昵称的相关条目，不能保证泛问“还记得我吗”就得到完整的旧事回顾。

QQ 对话目前不自动入库或整理为长期记忆；如需长期保存，仍须在桌面聊天使用“请记住：…”。当前只响应绑定主人的好友私聊。其他人即使加小号为好友也不会得到回复，群聊和临时私聊也不响应；没有自动通过好友申请或多人记忆分档功能。

## 消息与记忆行为

- 每条输入与回复最多 2000 个 Unicode 字符。只接收来自绑定主人、属于绑定机器人、时间在过去5分钟到未来30秒内的好友纯文字；含图片等混合消息整条忽略。
- 模型生成30秒总预算，草稿45秒有效。两秒内的新消息会取消旧草稿；触发节流的新消息暂不回复，稍等后重新发一条即可。
- 新主人消息使旧草稿失效，已经进入 socket 的发送无法撤回。保存设置、修改/删除/清空/恢复记忆会同步取消尚未发送的草稿，清除 QQ 短历史。认领绑定 Memory lease；发送准入在数据库锁内核验 lease，删除/恢复后旧草稿不能越过 UI 事件延迟。下一条认领的 lease 变化也会清历史。与 QQ 无关的记忆修改也保守取消。
- 前端未就绪时只保留一个最新待认领消息，最多45秒，内存保存；握手过程中也只保留一个最新合法主人消息。WebView 就绪后认领，认领前落盘最近消息标识。没有无限离线队列，也不补发应用退出期间消息。
- 最近消息去重表最多512项，仅保存机器人号、主人号、消息标识与接收时间。330秒内不淘汰新标识；达到上限时拒绝新消息，待窗口过期恢复。发送 API 回执须匹配 echo；成功、失败和结果不明分开处理。连接丢失、发送/回执超时均不自动重发，避免重复私聊；这是有界去重与保守不重试，不能保证跨崩溃的端到端恰好一次。
- QQ 使用独立内存短历史（最多8条），只有发送确认成功才加入助手回复；断线/配置/记忆变化后清空。不会混入桌面聊天、朗读、主动话题或共同体验。
- 长期记忆只读，限定绑定人设和昵称，最多6条/500字，内容经观察数据过滤。QQ 消息不会自动入库，也不能执行桌面工具。需要保存时，在桌面聊天输入“请记住：…”。本轮没有暴露公共 Memory/MCP 写接口。

## 本机存储与排查

配置位于应用配置目录的 `qq-onebot-v1.json`，包含本机 token；界面只显示“已保存 token”，不回显。去重标识在同目录 `qq-seen-v1.json`，不保存消息正文。Unix 新文件使用0600；Windows 沿用用户配置目录权限。不会把 QQ 正文或 token 加入日志、诊断或通用 AI 设置。清除 token 前关闭接入；空 token 输入默认保留原值。

连接/身份失败时检查 NapCat 已登录、正向 WS 已开启、地址端口、access token 和机器人 QQ 号。连接成功却无回复时核对好友身份、纯文字、绑定人设/昵称、模型配置和节流。结果不明时先查看 QQ 对话，不要假定未发送；本程序不会自动重发该条。

## 验证状态

关联 [issue #81](https://github.com/aaronfang/kxyy-desktop-pet/issues/81)。确定性 JS 覆盖独立成功历史、未知回执、取消、超时、身份变更、真实 Memory IPC 形状、观察过滤及认领幂等；Rust 覆盖过滤、登录身份、Bearer 握手、固定目标、echo 回执、初始消息缓冲、去重容量、认领与同步取消，使用本机模拟 OneBot，无真实 QQ 发送。

2026-10-25 已在 macOS 26.6.2 arm64、QQ 7.0.2-53644、NapCat 4.18.41 上核验小号身份、主人好友关系、仅本机监听、真实纯文字入站、出站成功回执，以及用户确认正式 App 收到回复。空主人昵称实际使用“元宝”，不能以打包个人画像的昵称推断有效分档；本次改为显式填写绑定昵称。随后发现默认加密资产缺少 `identity` / `displayName`，会使抽象模式自称“角色”；打包回归覆盖真实加密产物经 `loadAssets` 到抽象提示词的完整链路。

本机 NapCat 原生封包 Hook 曾导致 QQ Helper 被系统以 `CODESIGNING / Invalid Page` 终止。停用可选封包后端并保留原生库备份后，纯文字路线可运行；未关闭系统签名校验或 SIP。此为特定版本组合的本机兼容性处理，不能据此声称媒体功能或其他平台可用，升级 NapCat 后须重新核实。

仍未真实账号验收：陌生人/群聊/混合媒体不响应、生成期间连续消息、断线重连无重复、切换人设/删除记忆后无旧草稿；Windows 应用 UI 实机也未验收。CI 和模拟服务不能替代这些账号实测。

本轮自动门禁：`npm run test:gate` 通过（前置JS36、主JS526；Python、资源合同通过；Rust151 passed/1既有网络测试ignored，cargo check通过）。macOS独立identifier的debug App实测：默认关闭、表单独立保存、token保存后空白、模拟OneBot鉴权/登录核对、通过真实本地代理调用模型桩并向固定主人发送一次且获得匹配成功回执、陌生人无回复、关闭后无发送。全链路只用本机模拟服务，无真实账号、密钥或QQ外发。
