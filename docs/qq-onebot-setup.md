# QQ 主人私聊、语音消息与实验电话

采用与 Coopanion QQ world 相同的个人 QQ + NapCat / OneBot v11 路线。本项目使用本机正向 WebSocket，限定指定主人的好友私聊，默认关闭。文字、可选语音回复与主人语音转写共用当前人格和记忆分档；原生 QQ 电话另设实验开关，依赖独立桥和系统音频驱动。本轮增加了主人图片／图文和双向表情的实现，真实 QQ 媒体验收状态见下节；群聊、临时私聊、视频理解、游戏操控和自动好友申请暂不支持。

当前验收基准（2026-10-29，0.2.56）：macOS真实QQ语音收发、主人来电、流式回复、打断/挂断，以及语音消息记忆由电话正确回忆均已验证。普通对话自动整理，无需每句加“请记住”；明确保存还支持“请帮我记住，……”并返回真实保存回执。该自然说法在0.2.56补齐了前后端识别与回归；本次真实读回测试实际由自动整理完成，不将它误记成专用回执验证。Windows/Linux原生电话尚未验收。下方按日期保留的调查记录包含已解决的历史阻塞，最终状态见[实施计划](plan-qq-voice-and-calls-2026-10-27.md#最终验收与交付2026-10-29)。

## 搜索、表情和图片（2026-10-29，本地开发中）

- **搜索**：QQ 文字与主人语音转写按需搜索独立于“允许时下信息观察”（该开关控制兴趣缓存／主动资料）、完整／抽象人格和文字模型。DeepSeek Search 复用已保存的 DeepSeek Key；也可同时配置 Tavily Key。选择服务只决定优先顺序，失败、超时或无可用结果自动尝试另一家，各最多一次，总搜索等待最多12秒（双方均配置时各最多6秒，只有一家时最多10秒），前端等待最多14秒。显式搜索直接执行；无需触发词的提问由语义判断，天气、近期新闻等在判断服务异常时仍搜索。明确不联网、私人记忆与凭据不搜索。决策只带本轮问题与北京时间日期，不附人格、主人昵称、历史或记忆；服务商只收到必要搜索词，不抓取全文。QQ 回复附最多两条来源，区分真实成功、空结果、超时、限流及密钥／额度异常。搜索问答不进入 QQ 后续短历史或长期记忆。实时电话的搜索协商路径本次未修改。
- **接收表情**：QQ 内置表情按固定NapCat元数据的329个名称转为受控名称／编号；图片形式的表情包走看图路径，GIF / 动图仅取首帧，不声称理解完整动画。
- **发送表情**：角色可选择固定 QQ 表情；元元可使用随应用提供的表情包，其他人设不复用元元素材。每次最多一个，由本机允许列表转为消息段，模型不能指定本地路径或任意 URL。明确要求“发个表情”或“附一个微笑表情”时，即使模型漏标记也会由应用补上允许的表情；否定、讨论／转述和未知表情名不触发补足。文字模式可附表情；语音模式每条只发语音或单独表情，明确请求表情时优先单独发，跳过本条语音合成。单独表情的历史只记录实际发送行为，不把未发出的模型台词作为记忆。主人已确认图片与GIF首帧识别；主人已确认语音模式下单独表情正常显示；文字模式组合消息的客户端展示仍待单独验收。
- **看图**：每条最多3张；由已验证的机器人连接读取原始主人消息，重新校验发送人及消息 ID，再凭原始文件 token 获取 QQ 下载文件。仅读取固定 QQ 数据目录；PNG/JPEG/GIF/WebP，原文件≤8MiB，解码≤4096×4096，缩图≤1024×1024，重编码 PNG≤2MiB。超限或读取／识别失败会提示重试。沿用桌宠视觉设置：显式 Flash 文字模型直接看图，否则先由配置的视觉模型描述，再交当前人格回答。
- **图片记忆**：用户实际输入的文字可按普通对话整理；原图、表情标签、视觉描述及角色对图片的推测不进入长期记忆。纯图片不构造用户事实。若希望保存，应另发文字“请记住：……”；不会把附图自动当作已证实信息。
- **记忆粒度**：事实可单独保存；没有独立事件背景的复述不要求配套经历。一般事实查询优先同源事实，询问故事／经历时保留事件背景；不删除历史数据。电话同一回合的已完成播放片段合并整理，用户陈述只放一次。

确定性验收与实机未完成项见[本轮计划](plan-qq-search-media-memory-2026-10-29.md)。既有0.2.56语音验收不能代替本轮图片／表情验收。

## 配置

1. 注册一个独立个人 QQ 号，使用该号登录你自行部署的 [NapCat](https://napneko.github.io/)，与你的主 QQ 号互加好友。
2. 在 NapCat 的网络配置中启用 **OneBot v11 WebSocket 服务端**（正向 WS），监听 `127.0.0.1`，例如端口 `3001`。配置非空 access token；不要使用反向 WS 或远程监听。
3. 在桌宠“人设”页保存主人昵称与人格模式；QQ 自动跟随。默认元元昵称留空时使用“元宝”；自定义人设需填写昵称。
4. 打开“QQ 接入”，填 `ws://127.0.0.1:3001`、机器人 QQ 号、主人主 QQ 号；当前人设和记忆昵称只读显示，来自已保存的桌宠设置，无需额外绑定。
5. 填入与 NapCat 相同的 access token，开启 **开启 QQ 自动回复（立即生效）**。开关会自动保存这一页的配置并启动连接，无需另点保存；底部通用保存按钮不保存 QQ 配置。需要登录时，用机器人小号扫描设置内的二维码并在手机确认。状态显示 OneBot 已连接后，从主人号发一条文字。

桌宠与 NapCat 都须保持运行；首次握手用 `get_login_info` 校验真实登录号。主号与机器人号必须不同。QQ 回复复用当前文字模型和人格；保存人设、昵称或完整 / 抽象模式后，下一条 QQ 消息自动使用新设置。模型/API 未配置不会生成回复，连接成功只代表 OneBot 通道可用。

## 一键开启与关闭

- **macOS 开启**：打开元元桌宠 → 设置 → QQ 接入，开启 **开启 QQ 自动回复**。开关立即保存当前 QQ 表单并启动 QQ / NapCat、建立 OneBot 连接；已有配置无需重复填写或另点保存。桌宠检查 `/Applications/QQ.app` 已配置本机 NapCat 入口后，直接以 `--no-sandbox -q <机器人号>` 启动，不使用 `.command` 脚本，也不自动安装或修改 QQ。该参数沿用 NapCat 的启动方式，会关闭此 QQ 进程的 Electron 沙箱。
- **QQ 普通启动时**：开关会检查实际 QQ 可执行文件路径，向普通 QQ 主进程发送正常终止信号，等待退出后以 NapCat 方式重启。此操作会中断当前 QQ 会话，请先保存 QQ 中的工作。不会按名称批量杀进程，不会强杀拒绝退出的外部 QQ；失败会提示退出后重试。已用 NapCat 方式启动的外部 QQ 会复用，停止或退出桌宠时保留该外部进程。
- **需要登录时**：设置页显示登录提示和二维码。用机器人小号扫码并在手机确认，登录后桌宠自动继续连接，无需再次切换开关；二维码过期可点 **刷新登录二维码**。桌宠仅在 Rust 中读取本机 NapCat WebUI token，通过固定 `http://127.0.0.1:6099` 查询登录状态并在本机编码二维码；token、授权凭证及原始登录错误不进入 WebView、浏览器 URL、日志或记忆。二维码只在设置内存中展示，关闭接入或连接完成后移除。**打开 NapCat 管理页** 仅用于排查，日常连接无需操作管理页。更改 WebUI 端口或旧版 NapCat API 不兼容时，需自行排查。
- **关闭**：取消勾选同一个开关，立即禁用接入、取消未发送草稿、断开 OneBot，并结束桌宠启动的 QQ 及其 Helper。即使表单存在未保存的无效输入，也能关闭；配置写入失败时本次仍停止回复，并显示下次启动状态可能无法保存的提示。
- **下次启动桌宠**：保存为开启时，自动启动或复用 QQ / NapCat 并连接；保存为关闭时不启动。通过菜单栏 **退出** 会停止回复，并清理桌宠托管的 QQ 与本地语音服务；关闭设置或隐藏窗口不会退出服务。
- **改配置**：填好后可点 **保存 QQ 配置**；已开启时会同步应用并重新连接。人设与主人昵称自动跟随已保存的桌宠设置，旧 QQ 表单或旧配置文件中的绑定不会覆盖当前设置。Token 输入留空表示保留已存值，不会回显。
- **Windows / Linux**：同一开关管理 OneBot 连接，但本轮尚未实现这两个平台的 QQ / NapCat 进程启动和登录二维码。须自行启动 NapCat；关闭开关或退出桌宠保留外部 QQ。不能将 macOS 的一键启动能力视为全平台已支持。

界面分别显示进程、登录与 OneBot 状态。QQ 进程运行或开关开启不代表已登录、连接成功或可以回复；机器人登录号仍须通过 OneBot 握手校验。失败时开关会恢复到后台实际状态，表单的其他未保存输入会保留，重试不创建重复的托管进程。

## 人格、历史与好友范围

QQ 使用桌宠当前选中的人设卡、文字模型和在线提示词模式（完整/抽象），另附 QQ 传输约束；QQ 小号昵称不决定角色身份。默认元元的人设卡 ID 为空。切换角色或主人昵称时，只需保存桌宠设置，QQ 自动使用新人设和对应记忆分档。当前没有独立于桌宠的人格选择器。

QQ 短历史仅包含本次 QQ 会话中成功发送的问答，最多8条消息（约4轮），不会拉取 QQ 服务端旧记录，也不会复制桌面聊天记录。重启、断线、保存配置或记忆变更会清空短历史。读取长期记忆时只召回绑定人设和昵称的相关条目，对明确查忆问题，可结合上一条 QQ 用户话题补充一次检索（额外预算2秒）；泛问“还记得我吗”仍不保证完整旧事回顾。

QQ 与桌宠共用当前人设 / 昵称的长期记忆。可直接在 QQ 发送“请记住：…”获得真实保存回执；普通对话在回复发送成功后交给既有后台整理器，不保证每句话都形成长期记忆。当前只响应绑定主人的好友私聊。其他人即使加小号为好友也不会得到回复，群聊和临时私聊也不响应；没有自动通过好友申请或多人记忆分档功能。

## 消息与记忆行为

- 每条输入与回复最多 2000 个 Unicode 字符。只接收来自绑定主人、属于绑定机器人、时间在过去5分钟到未来30秒内的好友消息，可含文字、内置表情和图片。视频返回暂不支持提示，未知消息段仍拒绝。
- 普通模型处理30秒、图片处理60秒总预算，发送另有独立预算；未认领消息45秒有效，认领后的草稿最长180秒有效。未认领的普通文字最多合并八条、八秒；等待最新输入 2.5 秒后整体回应，达到八条立即处理。图片、语音和明确保存不合并；新输入取消已生成但尚未发出的旧草稿/余段。容量以外不建立离线积压队列，持续超快输入仍遵循最新消息策略。
- 新主人消息使旧草稿失效，已经进入 socket 的发送无法撤回。保存设置、修改/删除/清空/恢复记忆会同步取消尚未发送的草稿，清除 QQ 短历史。认领绑定 Memory lease；发送准入在数据库锁内核验 lease，删除/恢复后旧草稿不能越过 UI 事件延迟。下一条认领的 lease 变化也会清历史。与 QQ 无关的记忆修改也保守取消。
- 前端未就绪时只保留一个最新待认领消息，最多45秒，内存保存；握手过程中也只保留一个最新合法主人消息。WebView 就绪后认领，认领前落盘最近消息标识。没有无限离线队列，也不补发应用退出期间消息。
- 最近消息去重表最多512项，仅保存机器人号、主人号、消息标识与接收时间。330秒内不淘汰新标识；达到上限时拒绝新消息，待窗口过期恢复。发送 API 回执须匹配 echo；成功、失败和结果不明分开处理。连接丢失、发送/回执超时均不自动重发，避免重复私聊；这是有界去重与保守不重试，不能保证跨崩溃的端到端恰好一次。
- QQ 使用独立内存短历史（最多8条），只有发送确认成功才加入助手回复；断线/配置/记忆变化后清空。不会混入桌面聊天、朗读、主动话题或共同体验。
- 长期记忆限定当前人设和昵称，召回合计最多6条/500字，内容经观察数据过滤；明确查忆时最多一次规划和一次补充读取，失败回退。不会整库注入或跨昵称读取。
- “请记住：…”明确保存复用桌宠的本地 SQLite 事务、来源证据与幂等逻辑（正文最多500字）。只有实际提交成功才固定回复“已保存到长期记忆”；存储失败、过长、敏感或失效请求返回未保存。保存以实际收到并认领的主人消息为准，前端只提交凭据，不能任意指定内容或分档。请求及回执不重复进入普通整理。保存完成后即使 QQ 回执发送失败，记忆也可能已经保存，可在设置记忆页核对。
- 普通问答仅在 OneBot 匹配回执确认发送成功后入既有巩固队列；失败、结果不明、取消或过期身份不入队。“别记这段”等不保存要求、临时口令和敏感信息会跳过整轮（包括助手复述）。整理是异步的，可在设置“记忆”页查看任务状态；模型不可用时沿用重试/失败状态，不虚报完成。
- 在线文字模式会将允许记忆的问答批次发送到当前 DeepSeek 做巩固，本地 Ollama 模式留在本机；记忆数据库和结果仍只保存在本机。QQ 不获得桌面工具权限，也没有公共 Memory/MCP 写接口。

## 本机存储与排查

配置位于应用配置目录的 `qq-onebot-v1.json`，包含本机 token；界面只显示“已保存 token”，不回显。去重标识在同目录 `qq-seen-v1.json`，不保存消息正文。Unix 新文件使用0600；Windows 沿用用户配置目录权限。不会把 QQ 正文或 token 加入日志、诊断或通用 AI 设置。清除 token 前关闭接入；空 token 输入默认保留原值。

连接/身份失败时检查 NapCat 已登录、正向 WS 已开启、地址端口、access token 和机器人 QQ 号。连接成功却无回复时核对好友身份、消息类型、人设页已保存的昵称、模型配置和节流。结果不明时先查看 QQ 对话，不要假定未发送；本程序不会自动重发该条。

QQ 的提示词组装和模型请求由聊天 WebView 执行，即使桌面聊天窗口隐藏也须保持运行。聊天窗口显式设置 `backgroundThrottling: "disabled"`，避免 macOS 默认后台暂停使模型响应和30秒超时一起停住。Tauri 的该策略仅支持 macOS 14+，Windows/Linux 不生效；不能以配置回归或 macOS 结果替代其他平台的隐藏窗口实测。隐藏窗口仍会处理已启用的后台任务。

**0.2.54 延迟与Memory修复**：用户已确认原生电话能接通并收到语音回复。发现QQ旧入口未协商流式TTS，比本地通话多等待了整句合成；新版按本地服务能力协商边合成边播放，保留240ms启动缓冲，旧服务仍可回退完整合成。真实远端提速和打断仍待新包复验，不能用本机合成测量代替。电话成功回合还补齐后台Memory唤醒，先前3个任务已在启动恢复后整理为3条经历；新回合即时整理、明确保存与后续读回尚待验收。详细测量和测试见[实施计划](plan-qq-voice-and-calls-2026-10-27.md#真实电话已接通回复延迟调查与流式对齐2026-10-28)。

**0.2.55 语音输入恢复**：QQ云端转写可能在首次查询时还未提供文字。应用现在自动对同一条主人语音有限重试，最多3次、总等待不超过原有30秒；不必手动重发或开关服务。超过期限仍无有效文字时，设置的QQ区域显示识别失败，可重发或改发文字。用户已确认开发版连续两条语音均可收到回复；此前0.2.54电话也已确认明显提速、打断正常，新电话记忆可在应用持续运行期间自动整理。真实偏好的语音明确保存与电话读回仍待验收，最新证据见[实施计划](plan-qq-voice-and-calls-2026-10-27.md#语音消息首轮转写空结果的恢复2026-10-28)。

日常使用无需每条都说“请记住”。普通QQ文字/语音在回复发送成功后，电话在角色句段确认播放完成后，自动进入后台记忆整理；系统按内容提取经历、事实或约定，不保证每句都保留为长期事实。QQ私聊中的“请记住：……”是可选的明确保存入口：不经普通自动提取，直接尝试将指定内容保存为当前主人分档的一条“用户自述”事实，并返回真实的保存成功或失败回执。它不会自动置顶，也不保证之后每次回答都会召回；敏感内容、不保存要求、取消及身份失效检查仍适用。电话当前只有自动整理路径，不能把电话中模型说“记住了”当作明确保存回执。跨语音消息与电话的读回验收是开发验证步骤，不是日常聊天前置操作。


## 时间记忆与主动交流（2026-10-30，本地开发版）

QQ与桌宠、电话现在保留原消息时间；“昨天/今晚/明天”以说话当天为参照。历史事件、计划与当前状态分开呈现；旧记忆缺时间会标未知，不根据后台整理日期猜发生日。

设置→QQ主人私聊提供“主动交流”“主动交流通道”“静默时段”。这些控制同时协调桌宠与QQ，QQ关闭时仍可选桌宠通道。默认“安静”；建议先试“自然”：会话内有具体新内容时可同话题续话一次，长时联系闲置45分钟后才可能发言、至少间隔3小时、每天最多3次。“更主动”的长时联系为闲置20分钟、至少90分钟、最多5次。默认北京时间23–9不打扰；开始/结束相同表示不设静默。改完可点底部“保存”或“保存 QQ 配置”；未保存草稿和原生生效状态分别显示。

“自动”只选最近收到主人真实消息的一个渠道；QQ需已连接，桌宠需聊天窗口可见。生成、输入草稿、媒体、共同体验与通话期间避让。有合适的近期未完话题或已授权兴趣缓存才评估，模型可以保持沉默；不因到点强行问候。已送达且期待回答的提问，一次未回应延长等待、两次暂停；无需回应的分享不算未答提问，连续没有新互动仍逐渐降低联系频率。主人再次说话可解除普通退避。“先别主动找我”显式暂停，需“可以主动找我”恢复。失败/结果未知的准入尝试也保守计入次数，不自动重发。

文字模式可按完整意思发送1–3段，新消息到来会取消余段。主动文字同样最多三段；带表情的组合消息和语音模式保持单条；语音继续为语音或独立表情。历史和自动整理只接收原生确认的已发部分，不把未发段当成说过的话。主动候选/台词不构造成主人证据。确认送达的同话题续话沿用原始真实主人来源；外部资料分享不进入用户 Memory。后续真实聊天仍按既有流程整理。

macOS独立测试资料的原生WebView＋模拟OneBot已验证分段、插话、回执、主动准入、显隐与暂停恢复；本轮未向真实QQ发送测试消息，真实QQ自然性/跨夜及安装包、Windows/Linux尚待验收。完整实现、测试和步骤见[计划与验收](plan-temporal-memory-and-proactive-conversation-2026-10-29.md)。

### 自然聊天节奏与大肥鱼式活动（2026-10-30）

“自然”和“更主动”同时启用两条路径：会话内有具体新内容才补充一次；隔较长时间，有真实来源才重新找主人。前者不受 45 分钟闲置门槛限制：文字确认送达后最早 20 秒、语音送达后最早 60 秒重新询问模型，不是提前写好定时播放。等待答案、晚安/先忙、暂停、静默、电话或新输入会避让；没有新意思则不发。语音送达不代表已经听完，这些时间是待真人体验调整的保守初值。指定“桌宠聊天窗口”通道时不发 QQ 续话。

借鉴大肥鱼工程的活动路径复用已有授权兴趣缓存和真实约定/近期经历。独立活动簿维护“收集→形成感想→分享/休息”的分类小目标；重复来源不算进展，模型分享评分至少 13/20，每日选题评估最多 6/10 次。角色不能编造出门、吃饭或看完整部作品。设置可见固定分类进度、当前阻塞原因、最早再判断时间和最近决定；活动簿只存分类、指纹、计数与时间，不存资料正文或主人事实。

本轮 macOS 隔离原生 WebView＋模拟 OneBot 已验收全局保存、连续输入、分段、短时续话、等待、插话取消、暂停及真实来源夹具的目标分享。数据库核对确认只保存已发送前缀，没有伪造主人唤醒或外部分享入库。真实 QQ 听感/自然性、跨夜、安装包和 Windows/Linux 仍未验收。详见[本轮实施与验收](plan-natural-qq-interaction-2026-10-30.md)和[五个工程的一手源码研究](research-natural-qq-interaction-and-dafeiyu-2026-10-30.md)。

### 在哪里看主动状态与兴趣缓存（2026-10-31）

打开“设置 → QQ 接入 → 主动交流状态”。该区域显示原生已保存模式/通道、今日长时联系预留额度、阻塞原因、最早再次评估日期/时间、兴趣缓存开关/总数/感兴趣分类数/六小时内新鲜兴趣资料数、活动分类进度，以及最多 24 条固定状态决策。QQ 页可见时每 2.5 秒更新，也可点“刷新连接状态”。最早评估不是保证发送的闹钟；零新鲜资料也不代表记忆跟进或短时续话被关闭。

“打开兴趣缓存（时下信息）”直达“时下信息 → 允许时下信息观察”。开启并保存后，已有固定中文来源可以无需额外搜索 Key 采集；DeepSeek/Tavily 是按需搜索服务选择，不是主动缓存的独立开关。“设置感兴趣的话题”直达“人设 → 话题偏好”，至少一个分类标记为“感兴趣”并保存，之后可在“时下信息”点击“重新采集”。普通聊天的“参与方式”与 QQ 主动交流档位分别控制，不互相替代。

缓存摘要以已保存设置为准，和尚未保存的草稿区分。资料“六小时内新鲜”仅表示来源、兴趣和时间条件符合，尚未扣除使用历史、模型分享价值与联系预算。决策区仅显示固定状态与时间，不显示聊天、记忆正文或凭据。本轮自动验收和精简手动项目见[2026-10-31 验收报告](test-qq-natural-interaction-2026-10-31.md)。

### 每日联系目标与缓存后台补充（2026-10-31）

“时下信息”已启用时，程序每分钟检查已有固定来源的有效期，成功采集六小时后补充；失败从15分钟开始指数退避，最长六小时，重启保留退避。关闭观察后不再开启新的后台采集批次；已开始的请求可能仍会完成。后台来源不接收主人聊天、人格或记忆。主动选题现在先检查整个有界本地候选池，过滤过期、兴趣、重复与暂缓来源后再选择，普通聊天的三条资料上限不变。

设置 → QQ 接入可勾选“每日联系目标”（默认关闭），保存后生效。北京时间18点起，当天尚无确认送达的长时主动联系时，优先考虑真实约定、近期经历或兴趣资料；资料不足时，也可围绕已保存兴趣自然开启轻量话题，不虚构新闻或主人经历。当天最多准备两次；模型仍能放弃不合适的表达。这是择机联系目标，不保证固定时刻或每天必达：安静模式、静默、暂停、闲置/联系间隔、额度、忙碌、通话、断线均优先。桌宠专用通道不执行 QQ 每日目标，“自动”只有选中 QQ 时执行；希望用于 QQ 可直接选“QQ 私聊”。

确认送达（含已确认的部分消息）才满足目标；送达未知时当天不自动补发，重启也保留此限制。每日控制提示和外部来源不进入用户长期记忆。状态区显示今日目标准备次数、是否完成、后台补充/退避时间，以及缓存过期、无兴趣分类、来源用完、评估额度耗尽等具体原因。实际验证范围见[每日循环实施与验收](plan-daily-initiative-loop-2026-10-31.md)。

### 主动分享后的接话修复（2026-10-31）

此前主动资讯分享被当作外部内容完全排除出下一轮上下文，导致主人说“目前用不到”等依赖前文的短回复时，模型只看到旧聊天/召回资料而跳回旧话题。现将确认发送的分享台词单列为一次性临时观察：最多600字、十分钟有效、不保留原始来源、不进入普通历史或长期记忆；接话时不召回无关旧记忆，也不会误报本轮刚搜索。确认的部分发送仅使用已送达前缀。人格/记忆作用域切换、明确换话题、主动要求回忆、过期均清除该观察；送达未知不假定对方已收到。此观察只供紧接的一次普通回复使用，不恢复跨进程新闻历史。详见[排查与验证](fix-qq-share-followup-context-2026-10-31.md)。

### 搜索失败原因与等待上限（2026-10-31，初次排查）

搜索服务商与文字模型分别配置：使用DeepSeek聊天不表示搜索也使用DeepSeek，实际以“时下信息”保存的服务商为准。现将上游单次搜索总等待从4秒调整为10秒，前端等待12秒；依旧每轮最多一次，不自动重试或切换服务商。QQ能区分服务超时、限流、密钥/额度异常、服务失败和返回空结果，避免把网络问题说成没有联网权限或网上没有相关新闻。实际排查与未验收边界见[搜索超时修复](fix-qq-search-timeout-2026-10-31.md)。


### 搜索结果误过滤与双服务回退（2026-10-31）

上述初次超时修复并未解决全部原因：公开 AI 摘要中的 token、API key、密码学被前端私人观察过滤器误丢弃；只使用已选服务且仍有开关限制。现对公开搜索采用独立校验（保留真实凭据／注入拦截，私人 Memory 校验不变），QQ 按需搜索不再受缓存开关约束，并按可用 Key 在 DeepSeek／Tavily 之间回退。上方“搜索”条目是现行行为；初次排查的“不切换服务商”与旧等待时间已被替代。证据与验收限制见[本轮计划和验证](plan-search-auto-fallback-2026-10-31.md)。


### 自然技术资讯问法的漏搜（2026-10-31）

“有没有大模型相关的消息？偏技术向的”已复现搜索判断超时后未调用搜索服务的问题；现有兜底不再要求“最近／最新”，并保留技术方向、避免用户未要求的年月限制。公开资料可讨论系统提示词与工具调用；来源按同一最终预算打包，避免接口4条但模型仅看到部分。实际搜索与未搜索的提示分别处理，抓取时间不冒充发布时间。详见[原话复测、修复和能力边界](fix-technical-news-retrieval-2026-10-31.md)。


### 搜索语音概括与文字资料（2026-10-31）

QQ 在需要搜索时自动采用本轮研究路径，无需新增开关。语音模式先发简短语音，再在其后发独立文字资料卡；文字模式则先发文字概括。资料卡逐条列出与问题相关的细节、限制和真实来源链接，以及可用的发布时间和阅读范围。语音不会朗读资料卡或网址，搜索结果不进入长期记忆和后续普通聊天历史。

两家服务均可使用，不受人格模式、文字模型或兴趣缓存开关限制。每轮最多取六条候选，最终按相关性、技术方向、来源类型和可用时间信息筛选、去重，保留三条。优先论文页面、官方/项目站点；类型是域名启发分类，不代表论文已同行评审或任意 GitHub 项目属于官方。第一次缺少相关资料、正文或一手材料时最多再搜一轮，优先沿用刚成功的服务；全部检索共享24秒期限。

DeepSeek 请求正文，Tavily 请求 raw content。可用时提供有界页面正文摘录；不可用就标注“仅搜索摘要”，不把抓取时间当作发布日期，也不声称读完整篇论文/PDF。不是任意网页浏览器，不会执行来源中的指令或访问模型自造的链接。

资料以同一发送回执串行发送，最多三条文字（总5500字、每条不超过2000字）。概括确认成功后才发资料；语音明确失败可回退文字，未知结果不重发；后续资料失败不会重发已确认语音。新输入、切换人格、取消或记忆租约变化会阻止旧回复的后续资料。旧资料失败时保留已发送前缀，不在UI中声称全部送达。
