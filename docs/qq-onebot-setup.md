# QQ 主人私聊、语音消息与实验电话

采用与 Coopanion QQ world 相同的个人 QQ + NapCat / OneBot v11 路线。本项目使用本机正向 WebSocket，限定指定主人的好友私聊，默认关闭。文字、可选语音回复与主人语音转写共用当前人格和记忆分档；原生 QQ 电话另设实验开关，依赖独立桥和系统音频驱动。群聊、临时私聊、图片理解、游戏操控和自动好友申请暂不支持。

当前验收基准（2026-10-29，0.2.56）：macOS真实QQ语音收发、主人来电、流式回复、打断/挂断，以及语音消息记忆由电话正确回忆均已验证。普通对话自动整理，无需每句加“请记住”；明确保存还支持“请帮我记住，……”并返回真实保存回执。该自然说法在0.2.56补齐了前后端识别与回归；本次真实读回测试实际由自动整理完成，不将它误记成专用回执验证。Windows/Linux原生电话尚未验收。下方按日期保留的调查记录包含已解决的历史阻塞，最终状态见[实施计划](plan-qq-voice-and-calls-2026-10-27.md#最终验收与交付2026-10-29)。

## 配置

1. 注册一个独立个人 QQ 号，使用该号登录你自行部署的 [NapCat](https://napneko.github.io/)，与你的主 QQ 号互加好友。
2. 在 NapCat 的网络配置中启用 **OneBot v11 WebSocket 服务端**（正向 WS），监听 `127.0.0.1`，例如端口 `3001`。配置非空 access token；不要使用反向 WS 或远程监听。
3. 在桌宠“人设”页保存主人昵称与人格模式；QQ 自动跟随。默认元元昵称留空时使用“元宝”；自定义人设需填写昵称。
4. 打开“QQ 接入”，填 `ws://127.0.0.1:3001`、机器人 QQ 号、主人主 QQ 号；当前人设和记忆昵称只读显示，来自已保存的桌宠设置，无需额外绑定。
5. 填入与 NapCat 相同的 access token，开启 **开启 QQ 自动回复（立即生效）**。开关会自动保存这一页的配置并启动连接，无需另点保存；底部通用保存按钮不保存 QQ 配置。需要登录时，用机器人小号扫描设置内的二维码并在手机确认。状态显示 OneBot 已连接后，从主人号发一条文字。

桌宠与 NapCat 都须保持运行；首次握手用 `get_login_info` 校验真实登录号。主号与机器人号必须不同。QQ 回复复用当前文字模型和人格；保存人设、昵称或完整 / 抽象模式后，下一条 QQ 消息自动使用新设置。模型/API 未配置不会生成回复，连接成功只代表 OneBot 通道可用。

## 一键开启与关闭

- **macOS 开启**：打开元元桌宠 → 设置 → QQ 接入，开启 **开启 QQ 自动回复**。开关立即保存当前 QQ 表单并启动 QQ / NapCat、建立 OneBot 连接；已有配置无需重复填写或另点保存。桌宠检查 `/Applications/QQ.app` 已配置本机 NapCat 入口后，直接以 `--no-sandbox -q <机器人号>` 启动，不使用 `.command` 脚本，也不自动安装或修改 QQ。该参数沿用 NapCat 的启动方式，会关闭此 QQ 进程的 Electron 沙箱。
- **QQ 普通启动时**：开关会检查实际 QQ 可执行文件路径，向普通 QQ 主进程发送正常终止信号，等待退出后以 NapCat 方式重启。此操作会中断当前 QQ 会话，请先保存 QQ 中的工作。不会按名称批量杀进程，不会强杀拒绝退出的外部 QQ；失败会提示退出后重试。已用 NapCat 方式启动的外部 QQ 会复用，停止或退出桌宠时保留该外部进程。
- **需要登录时**：设置页显示登录提示和二维码。用机器人小号扫码并在手机确认，登录后桌宠自动继续连接，无需再次切换开关；二维码过期可点 **刷新登录二维码**。桌宠仅在 Rust 中读取本机 NapCat WebUI token，通过固定 `http://127.0.0.1:6099` 查询登录状态并在本机编码二维码；token、授权凭证及原始登录错误不进入 WebView、浏览器 URL、日志或记忆。二维码只在设置内存中展示，关闭接入或连接完成后移除。**打开 NapCat 管理页** 仅用于排查，日常连接无需操作管理页。更改 WebUI 端口或旧版 NapCat API 不兼容时，需自行排查。
- **关闭**：取消勾选同一个开关，立即禁用接入、取消未发送草稿、断开 OneBot，并结束桌宠启动的 QQ 及其 Helper。即使表单存在未保存的无效输入，也能关闭；配置写入失败时本次仍停止回复，并显示下次启动状态可能无法保存的提示。
- **下次启动桌宠**：保存为开启时，自动启动或复用 QQ / NapCat 并连接；保存为关闭时不启动。通过菜单栏 **退出** 会停止回复，并清理桌宠托管的 QQ 与本地语音服务；关闭设置或隐藏窗口不会退出服务。
- **改配置**：填好后可点 **保存 QQ 配置**；已开启时会同步应用并重新连接。人设与主人昵称自动跟随已保存的桌宠设置，旧 QQ 表单或旧配置文件中的绑定不会覆盖当前设置。Token 输入留空表示保留已存值，不会回显。
- **Windows / Linux**：同一开关管理 OneBot 连接，但本轮尚未实现这两个平台的 QQ / NapCat 进程启动和登录二维码。须自行启动 NapCat；关闭开关或退出桌宠保留外部 QQ。不能将 macOS 的一键启动能力视为全平台已支持。

界面分别显示进程、登录与 OneBot 状态。QQ 进程运行或开关开启不代表已登录、连接成功或可以回复；机器人登录号仍须通过 OneBot 握手校验。失败时开关会恢复到后台实际状态，表单的其他未保存输入会保留，重试不创建重复的托管进程。

## 人格、历史与好友范围

QQ 使用桌宠当前选中的人设卡、文字模型和在线提示词模式（完整/抽象），另附纯文字私聊约束；QQ 小号昵称不决定角色身份。默认元元的人设卡 ID 为空。切换角色或主人昵称时，只需保存桌宠设置，QQ 自动使用新人设和对应记忆分档。当前没有独立于桌宠的人格选择器。

QQ 短历史仅包含本次 QQ 会话中成功发送的问答，最多8条消息（约4轮），不会拉取 QQ 服务端旧记录，也不会复制桌面聊天记录。重启、断线、保存配置或记忆变更会清空短历史。读取长期记忆时只召回绑定人设和昵称的相关条目，对明确查忆问题，可结合上一条 QQ 用户话题补充一次检索（额外预算2秒）；泛问“还记得我吗”仍不保证完整旧事回顾。

QQ 与桌宠共用当前人设 / 昵称的长期记忆。可直接在 QQ 发送“请记住：…”获得真实保存回执；普通对话在回复发送成功后交给既有后台整理器，不保证每句话都形成长期记忆。当前只响应绑定主人的好友私聊。其他人即使加小号为好友也不会得到回复，群聊和临时私聊也不响应；没有自动通过好友申请或多人记忆分档功能。

## 消息与记忆行为

- 每条输入与回复最多 2000 个 Unicode 字符。只接收来自绑定主人、属于绑定机器人、时间在过去5分钟到未来30秒内的好友纯文字；含图片等混合消息整条忽略。
- 模型生成30秒总预算，草稿45秒有效。两秒内的新消息会取消旧草稿；触发节流的新消息暂不回复，稍等后重新发一条即可。
- 新主人消息使旧草稿失效，已经进入 socket 的发送无法撤回。保存设置、修改/删除/清空/恢复记忆会同步取消尚未发送的草稿，清除 QQ 短历史。认领绑定 Memory lease；发送准入在数据库锁内核验 lease，删除/恢复后旧草稿不能越过 UI 事件延迟。下一条认领的 lease 变化也会清历史。与 QQ 无关的记忆修改也保守取消。
- 前端未就绪时只保留一个最新待认领消息，最多45秒，内存保存；握手过程中也只保留一个最新合法主人消息。WebView 就绪后认领，认领前落盘最近消息标识。没有无限离线队列，也不补发应用退出期间消息。
- 最近消息去重表最多512项，仅保存机器人号、主人号、消息标识与接收时间。330秒内不淘汰新标识；达到上限时拒绝新消息，待窗口过期恢复。发送 API 回执须匹配 echo；成功、失败和结果不明分开处理。连接丢失、发送/回执超时均不自动重发，避免重复私聊；这是有界去重与保守不重试，不能保证跨崩溃的端到端恰好一次。
- QQ 使用独立内存短历史（最多8条），只有发送确认成功才加入助手回复；断线/配置/记忆变化后清空。不会混入桌面聊天、朗读、主动话题或共同体验。
- 长期记忆限定当前人设和昵称，召回合计最多6条/500字，内容经观察数据过滤；明确查忆时最多一次规划和一次补充读取，失败回退。不会整库注入或跨昵称读取。
- “请记住：…”明确保存复用桌宠的本地 SQLite 事务、来源证据与幂等逻辑（正文最多500字）。只有实际提交成功才固定回复“已保存到长期记忆”；存储失败、过长、敏感或失效请求返回未保存。保存以实际收到并认领的主人消息为准，前端只提交凭据，不能任意指定内容或分档。请求及回执不重复进入普通整理。保存完成后即使 QQ 回执发送失败，记忆也可能已经保存，可在设置记忆页核对。
- 普通问答仅在 OneBot 匹配回执确认发送成功后入既有巩固队列；失败、结果不明、取消或过期身份不入队。“别记这段”等不保存要求、临时口令和敏感信息会跳过整轮（包括助手复述）。整理是异步的，可在设置“记忆”页查看任务状态；模型不可用时沿用重试/失败状态，不虚报完成。
- 在线文字模式会将允许记忆的问答批次发送到当前 DeepSeek 做巩固，本地 Ollama 模式留在本机；记忆数据库和结果仍只保存在本机。QQ 不获得桌面工具权限，也没有公共 Memory/MCP 写接口。

## 本机存储与排查

配置位于应用配置目录的 `qq-onebot-v1.json`，包含本机 token；界面只显示“已保存 token”，不回显。去重标识在同目录 `qq-seen-v1.json`，不保存消息正文。Unix 新文件使用0600；Windows 沿用用户配置目录权限。不会把 QQ 正文或 token 加入日志、诊断或通用 AI 设置。清除 token 前关闭接入；空 token 输入默认保留原值。

连接/身份失败时检查 NapCat 已登录、正向 WS 已开启、地址端口、access token 和机器人 QQ 号。连接成功却无回复时核对好友身份、纯文字、人设页已保存的昵称、模型配置和节流。结果不明时先查看 QQ 对话，不要假定未发送；本程序不会自动重发该条。

QQ 的提示词组装和模型请求由聊天 WebView 执行，即使桌面聊天窗口隐藏也须保持运行。聊天窗口显式设置 `backgroundThrottling: "disabled"`，避免 macOS 默认后台暂停使模型响应和30秒超时一起停住。Tauri 的该策略仅支持 macOS 14+，Windows/Linux 不生效；不能以配置回归或 macOS 结果替代其他平台的隐藏窗口实测。隐藏窗口仍会处理已启用的后台任务。

### 既有私聊能力

关联 [issue #81](https://github.com/aaronfang/kxyy-desktop-pet/issues/81)。确定性 JS 覆盖独立成功历史、未知回执、取消、超时、身份变更、真实 Memory IPC 形状、观察过滤及认领幂等；Rust 覆盖过滤、登录身份、Bearer 握手、固定目标、echo 回执、初始消息缓冲、去重容量、认领与同步取消，使用本机模拟 OneBot，无真实 QQ 发送。

2026-10-25 已在 macOS 26.6.2 arm64、QQ 7.0.2-53644、NapCat 4.18.41 上核验小号身份、主人好友关系、仅本机监听、真实纯文字入站、出站成功回执，以及用户确认正式 App 收到回复。空主人昵称实际使用“元宝”，不能以打包个人画像的昵称推断有效分档；本次改为显式填写绑定昵称。随后发现默认加密资产缺少 `identity` / `displayName`，会使抽象模式自称“角色”；打包回归覆盖真实加密产物经 `loadAssets` 到抽象提示词的完整链路。

### 语音消息与实验电话（2026-10-28）

**设置入口**：QQ 设置区的“QQ 回复方式”选择文字或语音；“识别主人语音消息”单独开启，可以保留语音输入而只发文字。修改后点击 **保存 QQ 配置**（不是底部的通用保存按钮）。继续使用原有 QQ 自动回复开关启动、关闭服务，无须手动打开 QQ 或独立 `.command` 脚本；登录过期时按设置内的二维码提示登录。声音复用当前桌宠 TTS 设置，不在电脑扬声器额外播放。
