# 时间记忆与自然主动对话实施计划

依据[调研](research-temporal-memory-and-proactive-conversation-2026-10-29.md)，2026-10-29获用户授权设置Goal并实施。沿用当前主工作区，所有修改保留本地，不提交、不推送。

## 验收切片

1. **时间闭环**：消息保留可信时间与时区；巩固按源消息解析相对日期，事件时间与处理时间分开；所有渠道召回保留时间含义；跨日短历史明确分界。昨日晚饭不变成今晚，计划不自动成为完成事件，旧数据未知不猜。公开边界：Memory入队→巩固→召回、QQ接收→生成、桌宠/实时提示格式。
2. **多段回复**：文字按语义有界1～3段；段间新消息／切身份／关闭／删记忆取消余段。语音保持单条或独立表情。每段实际成功回执才入历史，部分成功、失败、未知不重发，不将未送内容写入Memory。公开边界：QQ原生准入→OneBot回执与JS真实接线。
3. **主动关心**：可见设置控制安静／自然／更主动；原生有界调度在窗口隐藏时仍运行；有来源、有时限的未完话题可以提出send/wait/drop，允许沉默。夜间静默、预算、同话题冷却、无人回应退避两次后暂停、主人恢复、睡眠不补过期、人格/昵称/lease隔离有效。独立主人限定主动准入，不伪造入站消息。
4. **真实兴趣分享**：复用已授权本地时下缓存和对话中的真实资料，有具体关联才分享；来源去重、跨日保留有限候选；不启动新的任意后台浏览，不虚构生活。主动内容与内部候选不成为用户事实，搜索派生内容继续排除长期记忆。
5. **协调与验收**：桌宠同源主动策略与QQ共用预算／取消边界，不与电话和普通生成抢话。现有通话Director及播放证据不改音频端点。每个功能先Red→Green，受影响集成套件后完整`npm run test:gate`。macOS开发版验收，Windows/Linux及无法执行场景明确标未运行；需要用户收听/收消息的步骤尽量合并验收。

## 实施决策

- 以先修时间再加主动为顺序；先做文字多段，语音单条。
- 自动主动默认关闭，由设置明确开启；用户本次授权允许实现和检验，实际对主人测试发送沿用主人发起验收，或仅在明确开启主动功能后按设置发送。
- 主动不依赖搜索触发词，不因定时到点强制说话；首版真实分享使用已有授权缓存，不扩大采集范围。
- 真实QQ没有可靠已读/输入状态，不据沉默推断情绪；发送回执不代表听完。
- 时间与主动调试只记固定状态和计数，不记录私人正文、Memory或凭据。

### 用户试用步骤

1. 开发版设置→QQ主人私聊→主动交流，选择“自然”、通道“QQ私聊”或“自动”，保存。保持默认夜间静默。有未完的近期真实话题或授权兴趣资料才会开口；达到间隔不保证一定发言。桌宠通道要求聊天窗口真实可见，QQ可在窗口隐藏时使用。
2. 文字模式正常聊一个需要展开的话题；收到第一段后插话，确认后续旧段停止。语音仍为一条语音或独立表情，不连续拆成多条语音。
3. 说“先别主动找我”应停止主动，再说“可以主动找我”恢复。连续两次未回应也会暂停；一般消息可解除无人回应退避。关闭QQ开关会停QQ自动回复；如还要停止桌宠主动，把主动交流切回“安静”。
4. 以真实日期询问昨天/今天的不同事件，观察它是否区分已结束事项和当前状态。旧记忆缺少可信时间时只能说“之前”；不会把整理日期当成发生日期，也不会重写旧记录来猜日期。

### 限制与迭代边界

自然性仍需本人试用；分钟数是可用的保守首版参数，不宣称最佳。“同话题”冷却目前按同scope的规范化内容摘要与模型所见短历史实现，**不是语义聚类**。中文相对日期解析只覆盖已测试的明确日期/今天/昨晚/昨天/前天/明天/后天等表达，模糊时间保留未知。首版不加入虚构生活、自动刷站/视频或新的公网服务。DeepSeek仍可能理解错时间，提示与检索证据不能保证模型零误判。
