# 元元带聊 v2：实时对话节奏与深聊优化规格

日期：2026-08-08
状态：核心实验切片已实现，待真实设备体验验证
首要范围：本地 Qwen3 / CosyVoice 实时通话的“元元带聊（实验）”
后续范围：验证稳定后，将同一对话策略接入文字聊天

## 1. 目标

当前“元元带聊”能主动开场和有限续说，但仍容易出现：话题难接、回答快速收口、家常话题浅、短回应后停止、连续提问像采访，以及思考期间长时间没有反馈。

v2 的目标是让元元承担约 70% 的话题供给和推进工作。用户只用短句、附和、简单选择或打断，也能自然参与；同时保留用户随时开口、暂停、换题和挂断的控制权。

首版成功不等于“说得更多”，而是：

- 元元先贡献具体内容，再向用户索取内容。
- 有意义的话题可以渐进深入至少三轮。
- 用户短回应不会立即结束话题或触发无关换题。
- 不连续盘问，不急着建议或总结收口。
- 思考可以变慢，但等待过程必须可感知。
- 新策略不得明显增加关闭思考时的首段可听延迟。

## 2. 非目标

- 首版不实现用户说话期间的语义抢话。当前只有 final ASR，不能可靠理解尚未结束的句子。
- 首版不改 Volcano 实时协议或为 Volcano 宣称主动带聊能力。
- 首版不把文字聊天一起迁移；文字侧只保留未来复用 seam。
- 首版不让 learned Memory、网页内容或对话状态修改 persona/system 规则。
- 首版不做隐藏好感度、心理诊断或自适应人格推断。
- 首版不以增加第二次 LLM 分类调用换取意图识别。

## 3. 产品模式与回退

- 新行为只在“元元带聊（实验）”启用。
- “跟随用户”和“自然轮流”保持现有稳定行为，作为对照和回退。
- 实验稳定前不得替换所有模式，也不得接入文字聊天。
- 挂断是唯一权威的通话结束信号；系统不刻意制造话题结束或总结式告别。

## 4. 核心对话策略

### 4.1 70/30 主导

元元负责约 70% 的内容供给与推进，用户负责约 30% 的选择、补充和方向调整。每轮优先遵循：

1. 接住用户刚才的具体表达。
2. 增加一个新观点、细节、例子或有依据的小故事。
3. 必要时留下一个具体、低负担的回应入口。

禁止用泛泛的“你呢”“还有吗”冒充推进。

### 4.2 三种推进动作

对话导演在以下动作间轮换，而不是每轮都用问题结束：

- `expand`：展开观点、细节或故事，不要求用户立刻回答。
- `offer-entry`：提供一个具体、低负担的入口，例如二选一或“更像哪一种”。
- `deepen`：接住用户用词，沿感受、原因、价值判断或个人选择深入一层。

约束：

- 一轮最多一个明确问题。
- 不连续两轮只提问题。
- 用户刚提供较多内容时，下一轮优先回应和展开。
- 用户只说“嗯、哈哈、是啊”时，先贡献新内容，再递入口。
- 连续两次没有兴趣信号后，才允许考虑换题。

### 4.3 渐进式深聊

话题默认沿下列阶梯推进：

```text
事实 -> 感受 -> 原因 -> 价值判断 -> 经历/选择 -> 未来行动
```

- 不要求每个话题走完整条阶梯。
- 用户持续有兴趣时才向下一层推进。
- 用户回避、转移、沉默或说“没事”时立即降低深度。
- 可以深入用户已经打开的门，但不替用户打开创伤、疾病、家庭冲突、恋爱状态、经济状况等敏感的门。
- 用户主动谈到敏感内容时一次只深入一层，并始终保留退出空间。

### 4.4 默认陪聊，按需建议

默认顺序为：理解处境 -> 帮用户说清感受或矛盾 -> 展开一两层 -> 用户明确求助后再给建议。

- 用户倾诉时不立即列方案或讲人生道理。
- 避免使用“总之”“所以你应该”收口。
- “你怎么看”“我想听听你怎么想”进入观点贡献，而不是反问。
- “你觉得怎么办”“换成你会怎么做”视为本轮建议授权。
- 未完成但有意义的分支可以成为低频回溯候选。

### 4.5 温和分歧

元元可以拥有稳定观点并温和反驳：

- 先准确接住用户核心意思，再表达不同看法。
- 分歧针对观点和选择，不评价用户人格。
- 必须给出具体理由或例子，不为制造戏剧性而唱反调。
- 用户明显只在倾诉时先陪伴，不立即辩论。
- 用户说“不想争这个”后立即退回陪聊。
- 当前事实与个人看法必须明确区分。

### 4.6 低频留白

允许在情绪、关系、调侃和个人观点中使用欲言又止的表达，例如“我刚才其实有点想说……算了，你先讲”。

- 每约 5 个助手回合最多一次。
- 不用于事实说明、联网信息、安全提醒和明确求助后的建议。
- 留白前必须提供足够语境。
- 不使用被动攻击式“算了，当我没说”逼用户追问。
- 生成必须正常结束；不得用传输中断伪造留白。

## 5. 话题连续性

### 5.1 会话话题账本

账本仅存在于当前通话，固定有界，至少记录：

- 当前话题标识和深度层级。
- 用户兴趣信号。
- 尚未展开的重要分支。
- 当前会话已经使用或封存的话题。
- 最近使用的推进动作和连续主动轮数。

账本正文、topic key 和分支文本不得进入诊断；挂断后清空。

### 5.2 低频回溯

- 回溯最多占主动话题转换约 20%。
- 同一话题每次通话最多主动回溯一次。
- 只允许明显情绪、长期困扰、未完成决定、重要关系、用户目标等具有个人意义的分支。
- 吃饭、天气、普通新闻和随口闲聊默认不进入回溯候选。
- 当前有高参与度的新话题时不得为了回溯而打断。
- 用户说“别聊这个”后，本次通话封存该话题。

### 5.3 换题

- 一次短回应不是低兴趣证据。
- 连续两次低兴趣信号后才允许换题。
- 换题前至少完成一次同话题续说。
- 轻松新闻可以提供新话头，但不得把聊天变成新闻播报。

## 6. 语音节奏

### 6.1 动态等待

首版使用固定、可测试的动作相关等待，不推断用户性格：

| 上一动作 | 建议等待 |
|---|---:|
| 明确提问 | 约 8 秒 |
| 低负担入口 | 约 6 秒 |
| 仅展开观点 | 约 4 秒 |
| 同话题续说后准备换题 | 约 14 秒 |

- 用户出现候选语音时，所有主动计时立即让路。
- 连续主动说满 3 次仍没有用户回应时停止主动生成并安静等待。
- 第一版不根据用户历史自动调整这些时间。

### 6.2 回复时长

- 简短接话或共鸣：约 3-8 秒。
- 普通观点展开：约 10-18 秒。
- 深聊、故事或用户明确要求多说：约 20-35 秒。
- 35 秒是自然让出话轮的软提示点，不是硬截断；用户明确邀请继续时可以更长。
- 始终按稳定句流式生成和播放，不等待整篇完成。
- 用户打断后仍只把真正播放完成的内容加入可听历史。

### 6.3 思考反馈

思考时间可以增加，但等待必须可感知：

- 用户说完后立即显示“思考中”视觉状态。
- LLM 请求约 5 秒后仍没有任何正文输出时，才允许播放一次运行时生成的中性填充，如“嗯……让我想想”；正常等待只显示 UI 状态。
- 每轮最多一次，变体低频轮换。
- 不使用“我觉得……”等已经承诺语义方向的填充。
- 正文准备好后等待填充自然结束再接入；用户开口时立即停止并让路。
- 填充不进入可听历史、Memory、recap 或正文诊断。
- 当前仓库只提供无文本的 `onThinkingFillerOffer` 回调和 UI 状态；未发现经审核的元元预录填充素材前，不播放或动态合成语音填充。
- 文字聊天未来使用可原位替换的瞬时状态，不留下独立历史消息。
- “渐进式深聊”不自动等同于开启思考；用户设置或明确复杂分析意图可以启用更长推理。

### 6.4 倾听回应议题

首版可预留但不必须启用“非语义 backchannel”实验：

- 仅在用户连续说话超过约 4 秒并出现自然小停顿时，播放一次极短、非承诺回应。
- 只能使用“嗯”“我听着呢”等预生成、审核过的片段。
- 不停止录音、不截断用户、不进入历史或 Memory。
- 用户恢复说话立即停止；回声消除或设备能力不可靠时禁用。
- “对”“我也是”等需要理解未完成语义的回应禁止使用。

真正的语义抢话必须等待可靠的流式 partial ASR、稳定分句、partial 修订和不丢用户后续语音的独立实验，不属于 v2 首版。

## 7. 自然语言控制

### 7.1 硬控制

硬控制改变通话状态，使用高精度本地规则和同义表达匹配：

- 暂停主动陪聊：“安静一会儿”“先别说”。
- 让用户讲完：“先听我说”“你先听我讲完”。
- 恢复：“你可以说了”“继续”。
- 换题或封存：“换个话题”“这个不想聊了”“别聊这个”。

宁可保守，不让 LLM 猜测硬控制。状态变化不写入长期 Memory。

### 7.2 软引导

软引导只影响本轮或当前话题：

- `invite-opinion`：“你怎么看”“我想听听你怎么想”。
- `invite-advice`：“你觉得怎么办”“换成你会怎么做”。
- `deepen`：“深入聊聊”“这个可以多说一点”。
- `lighten`：“轻松点”“别聊那么沉重”。
- `concretize`：“说具体点”“举个例子”。

先用确定性模式路由，再把固定提示交给主 LLM；不新增分类 LLM 调用。即使未命中规则，主 LLM仍按普通自然语言理解，不返回“未识别指令”。

## 8. 内容来源与真实性

元元主动贡献内容使用三层来源：

1. persona 中有依据的经历、偏好和观点。
2. 基于稳定人设表达的新观点。
3. 明确标为假设的联想，例如“要是我”“换成我可能会”。

禁止编造“今天刚发生”“刚和谁聊过”“最近亲身经历”等虚假生活轨迹。

### 8.1 用户话题偏好

- 当前通话内快速记录兴趣信号，但一次短回应或沉默不能推断不喜欢。
- 只有用户明确表达或多次会话出现稳定证据时，才形成长期偏好候选。
- 设置页提供独立“话题偏好”编辑区，包含感兴趣、不感兴趣和中立。
- 使用基础分类加自定义标签；自动推测与用户手动添加必须区分。
- 用户手动设置优先级最高，模型不得覆盖。
- “不感兴趣”仅禁止主动发起；用户主动提到时仍可回应。“不要再提”使用更强封存语义。
- 网络正文不进 Memory，只允许保存“用户对电影话题感兴趣”等抽象偏好及证据引用。

当前实现：设置页已提供基础分类和自定义标签的“感兴趣 / 中立 / 不主动聊”编辑区；结构化条目由 Rust 有界归一化并保存在本机设置中，手动项覆盖同名推测项。文字用户输入和实时 final-ASR 会生成仅含固定类别、置信状态和证据枚举的 inferred 候选；它们仍需用户在设置中编辑/确认，不能直接改写 persona 或长期 Memory。

## 9. 新鲜互联网话题

联网方案已经单独调研，权威结论见 [桌面陪聊的近期互联网信息来源与预取架构调研](./research-fresh-web-topics-2026-08-08.md)。本规格只记录已确认的产品决定：

- 继续使用显式“允许时下信息观察”开关。
- 用户开启后，后续应用启动允许自动预取，无需每次确认。
- 启动预取只使用固定来源和显式兴趣分类，不发送聊天、Memory、persona 或设备隐私。
- 自用测试阶段的启动层使用 15 个固定中文/中国区来源：中新网 RSS、百度热榜、B 站热门、IT之家 RSS、Steam 限时免费、Steam 新游、Epic 限免、App Store 中国区新游、豆瓣电影、汽水音乐、网易云音乐、城市餐饮搜索、携程餐厅榜、携程景点榜，以及末级兜底的必应中文分类搜索。Steam 热门、下厨房、机核、GDELT/HN 不参与默认预取；Tavily 留给明确搜索意图的按需增强。
- 实时语音和文字聊天当前共用 Rust 管理的短期话题缓存；实时侧只有协商 `fresh-topic-v1` 的本地/CosyVoice 服务消费它。
- `publishedAt` 与 `fetchedAt` 必须分开；搜索失败不能静默伪装成“模型没关注”。
- 网页内容始终是不可信 observation，不写 Memory、persona 或诊断正文。

网络获取不是首个对话导演实现切片，但接口必须允许以后注入有界话题候选。

## 10. 对话导演模块

### 10.1 Seam

新增一个纯状态模块作为对话策略 seam。调用方提交固定事件，模块返回固定动作；模块不直接访问 WebSocket、计时器、ASR、TTS、Memory、网页或 LLM。

建议最小 interface：

```js
const director = createConversationDirector({ mode, limits, delays });
const actions = director.dispatch(event);
const snapshot = director.snapshot();
```

固定输入事件至少包括：

- `session-started`
- `user-turn-final`
- `assistant-reply-planned`
- `playback-completed`
- `silence-deadline`
- `speech-candidate`
- `hard-control`
- `hangup`

固定输出动作至少包括：

- `schedule-proactive`
- `cancel-proactive`
- `request-reply`，附带固定 move/policy/depth 枚举
- `pause-leading`
- `resume-leading`
- `seal-topic`
- `show-thinking`
- `offer-thinking-filler`
- `stop-thinking-filler`

接口不暴露 prompt 文本、topic 正文、Memory id 或 provider 细节。具体 prompt 由 Python adapter 根据固定枚举映射；JS adapter 负责现有计时器、播放回执和打断事件。

### 10.2 有界状态

- 话题与开放分支队列各最多 8 项。
- 最近推进动作保留固定小窗口。
- 每话题主动轮数、回溯次数、低兴趣计数和提问连续数均为有界整数。
- 所有计时使用单调时间；模块只返回 delay，不自行创建 timer。
- `hangup` 后 dispatch 不再产生主动动作，snapshot 不含文本。

### 10.3 现有协议边界

- `managed-v1`、`local-v1`、KXAU、播放完成回执、候选暂停和 audible history 规则不变。
- JS/Python 镜像的 engagement/control 固定枚举需要一起更新并用表驱动测试锁定。
- 不从 managed chunk progress 推断文本，不把控制提示写入历史。
- Volcano 仍保持现有行为。

## 11. 测试 seam

实施前需要确认以下公共 seam，测试只通过这些 interface 验证行为：

1. **纯对话导演 seam**：事件序列输入，固定动作与无文本 snapshot 输出。
2. **JS 实时会话 seam**：播放完成、候选语音、timer 和 WebSocket 固定消息之间的行为。
3. **Python 对话策略 seam**：final ASR 文本到固定 control/soft-intent 枚举，以及枚举到有界 prompt hint 的映射。
4. **端到端确定性回放 seam**：现有假 WebSocket/假播放回执下，用户短回应、三轮深入、暂停、换题、思考填充和挂断的可观察事件。

不测试私有字段、内部 helper 调用次数或 prompt 的完整逐字快照；只测试固定枚举、动作、时间边界和隐私约束。

## 12. 硬性验收

- 固定回放中至少 80% 的短回应得到“新增内容 + 可接入口”。
- 硬控制测试集 100% 通过，近似但非控制语句不得误触发。
- 不出现连续两轮纯提问。
- 用户已展开时不得立即切题或进入未经请求的建议模式。
- 用户开口后，主动语音和思考填充按现有打断时限让路。
- 对话导演不新增 LLM 请求；缓存命中路径不增加可感知等待。
- 关闭思考时，首段音频延迟相对当前基线的 p95 回归不超过 500ms。
- 思考超过约 1.5 秒仍无正文时有视觉反馈；继续延迟时最多一次中性填充。
- 无意义话题不得进入回溯；同一话题每通话最多主动回溯一次。
- 所有新增队列固定有界，挂断后会话状态清空。
- 诊断只保存固定枚举、计数和时长，不保存 ASR、话题、网页或 Memory 正文。
- 真实通话体验通过前不得接入文字聊天。

## 13. 实施切片

每个切片遵循 red -> green，一次只增加一个可观察行为：

1. 纯对话导演：动作轮换、连续提问保护、低兴趣计数和 3 次主动上限。
2. 硬控制与软引导分类：JS/Python 镜像固定枚举。
3. 实时 JS adapter：动作相关 delay、timer 取消和现有 `proactive_turn` 映射。
4. Python prompt adapter：`expand|offer-entry|deepen`、陪聊/建议、温和分歧和低频留白提示。
5. 思考状态与一次性中性填充；不污染 audible history。
6. 有界话题账本与低频重要分支回溯。
7. 可编辑话题偏好候选和设置 UI。
8. 新鲜话题缓存与实时注入，按独立调研分切片实现。
9. 固定回放、性能基线和真实通话体验。
10. 体验通过后设计文字聊天 adapter，不复制策略实现。

## 16. v2.1 后续实施顺序（2026-08-08）

以下五个切片按顺序实施。每个切片必须通过自己的确定性测试和前一切片的回归测试，不能横向铺开后一次性联调。

### 16.1 新鲜互联网话题预取与统一缓存（代码已实现，待测试版验收）

权威 seam 是 Rust 管理的 `FreshTopicService`：

- `prefetch(reason=startup|settings|manual)`：仅在用户已开启网页观察时异步刷新，不阻塞窗口、语音服务或模型预热。
- `query(query?, categories?, maxItems)`：文字聊天和实时通话共用；优先读磁盘/内存缓存，返回固定状态和有界 observation。
- provider adapter 只接受固定 HTTPS 端点。启动预取不发送聊天、Memory、persona、联系人或设备信息。
- observation 固定包含来源、标题、`publishedAt?`、`fetchedAt`、短文本、类别和 locale；抓取时间不得冒充发布时间。
- 缓存最多 200 条，按话题偏好在去重后保留：`neutral=10`、`interested=15`、`not-interested=0`；每次对话最多注入 3 条，每条短文本最多 300 字、整块最多 1200 字，7 天硬过期，正文不得进入 Memory、persona 或诊断。
- 固定来源按分类路由，并按分类确定优先级：影视优先豆瓣剧情简介；游戏在一个用户分类内按新游与限免交替，Steam/Epic/App Store 分别提供电脑限免、电脑新游/限免和中国区移动新游；音乐优先汽水音乐、网易云兜底；科技优先 IT之家；美食在有地点提示时优先城市餐饮搜索，否则使用携程餐厅榜；旅行优先携程景点。菜谱来源不再作为食品兜底，专业源不足后才使用同类后备和必应分类搜索。设置页显示来源、覆盖分类、状态、候选数、入选数和时间，并提供只读状态刷新与受 30 秒来源冷却保护的手动重新采集。
- 当前只做分类级匹配；“适合休闲玩家”“适合通勤”等查询词与具体候选的细分相关性排序列为后续优化，不能在当前实现状态中宣称已完成。
- 来源摘要先重建 XML 预定义实体，再解码嵌套 HTML/XML 实体、移除 script/style 块、标签和页面操作词，最后做 240 字上限与提示注入过滤；标题与摘要相同不冒充简介。工作成长明确排除百科、字典和“是什么意思”类词条。
- 本地/CosyVoice 通过显式 `fresh-topic-v1` 能力协商消费缓存；旧服务和火山降级为 `none`。

验收 seam：Rust 的 `FreshTopicService` 公共 interface、前端 observation adapter、JS/Python 私有实时协议和固定三轮对话回放。

当前实现还覆盖：启动后异步预取、地点提示变化后的有界刷新、15 个来源的分类适配、六小时自动刷新 TTL、30 秒手动刷新冷却、10/15/0 偏好配额、同一日常事件族最多两条、可选 Tavily 增强、7 天条目过期和旧缓存保留；“推荐几首歌/两部新片/三本书、哪里有好吃的、去哪玩”等自然表达会路由到对应分类，第一人称近况陈述不会仅因包含“最近”而触发。实时侧只有明确协商 `fresh-topic-v1` 才消费，旧服务和火山不注入。

### 16.2 DeepSeek 实时 LLM 对话导演一致性（统一路径已实现，待显式回放验收）

- 本地/CosyVoice 的语音后端与文字 LLM provider 解耦；`textProvider=deepseek|local` 都必须消费同一组 `conversationPlan`、控制枚举、话题回溯和新鲜 observation。
- 不按 provider 复制导演状态机，不让 DeepSeek 路径绕过 `expand|offer-entry|deepen`。
- DeepSeek Key 缺失、SSE 失败或超时必须返回固定错误并保持通话可恢复，不得回退为伪当前信息。

验收 seam：Python LLM 请求快照、假 SSE 回放和 JS/Python 端到端导演枚举回放。

当前实现已由 Rust 统一代理根据 `textProvider` 选择 DeepSeek 或 Ollama/Qwen3；Python 只请求 `provider=text`，因此 `conversationPlan`、Memory、回溯和新鲜话题不按 provider 分叉。

### 16.3 自动话题偏好推断（首版已实现，待用户编辑体验验收）

- 首版只接受用户明确表达的喜欢、不喜欢、恢复中立和“不要主动聊”；不从一次沉默、短回应或模型猜测推断长期偏好。
- 自动结果以 `source=inferred` 候选保存，用户手动项优先且永不被覆盖。
- 候选必须有固定类别、规范化标签、置信状态和不含原话的证据引用；网页正文不得成为偏好证据。
- 设置页继续允许会后编辑；删除或改为中立后不得被同一旧证据立即恢复。

当前实现接入文字用户输入和实时 final-ASR；候选只保留固定类别、`confidence` 和不含原话的 `evidence` 枚举，合并由 Rust 有界命令完成。

验收 seam：纯分类/归一化模块、Rust 有界合并 interface、设置 UI 和实时 final-ASR adapter。

### 16.4 用户实测前验收（待人工执行）

- 固定查询覆盖全部启用分类；验证 RSS/JSON/HTML 解析、网页格式清洗、缓存命中、过期、离线、来源限流/格式变化、分类专业源优先级、偏好 10/15/0 配额、手动刷新冷却、Tavily 无 Key/错 Key/超时和 provider 状态。真实网络 smoke 当前保持 ignored，只在人工验收时分别报告来源候选、入选和分类短缺，不以 HTTP 成功代替内容可用，也不要求外部来源在每次运行都填满配额。
- 本地 Qwen3 与 DeepSeek 各回放至少三轮短回应深聊，验证新增内容、来源表达、同题深入和不播报新闻摘要。
- 建立可重复 TTFA 基线，记录关闭/开启思考、新鲜缓存命中、DeepSeek、本地 Qwen3 的 p50/p95；缓存命中路径相对基线不得回归超过 500ms。
- 自动化仍不能替代麦克风、AEC、音质和真人等待感；这些保留为测试版人工 runbook 的明确项目。

执行入口：[实时语音设备验收清单](./realtime-device-acceptance.md)。在该清单完成前，不把“已接通 DeepSeek”或“思考填充自然”宣称为真实设备已验收。

### 16.5 真实语音思考填充（运行时方案已实现，待实机听感验收）

- 只使用经过审核、声音授权明确的本地素材，或明确标为运行时合成的缓存结果；不得把动态合成伪装成预录。
- 每轮最多一次，正文准备好后自然衔接，用户候选语音立即停止并让路。
- filler 不进入 audible history、recap、Memory、长期偏好或正文诊断。
- 没有合格素材、播放能力或时序竞争失败时保持现有视觉状态，静默降级。

当前实现使用本地/CosyVoice 当前 TTS 运行时生成“嗯，让我想想……”，通过独立 `thinking_filler` 消息播放，不写入 audible history、recap、Memory 或诊断；主动 welcome 首句永不触发，5 秒内出现正文、用户候选语音或 TTS admission 竞争时跳过。

此切片依赖 16.4 的 TTFA 和打断基线；接入后必须重跑同一套基线，确认 filler 不挤占正文 TTS admission。
