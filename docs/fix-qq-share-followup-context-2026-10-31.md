# QQ 主动资讯分享后的上下文断裂

日期：2026-10-31。仅本地修复，未提交/推送。

## 证据和原因

用户报告：角色主动分享系统隐私权限，主人表示目前用不到，角色却接回了不相关的饮食话题。现有运行日志只有服务/音频阶段，没有完整模型请求；无法从日志证明饮食词具体来自哪条旧历史或召回记录。没有为定位新增私人正文日志。

代码与回归测试确认缺陷：`createQqPrivateChat.initiate` 对 `external:true` 的确认消息完全不保留上下文；下一次 `receive` 仍使用旧普通历史和召回。下一轮生成实际缺失刚发出的分享，泛指回复因此失去指代对象。之前验证轻量每日联系（非external）的用例没有覆盖此类外部资讯。

## 修复边界

- 只暂存已确认发送的分享台词，最多600字，单独的进程内观察，最多十分钟；不保存原始缓存/网址/来源摘要。不进入普通短历史、召回规划、用户长期 Memory 或诊断。
- 确认外部分享开启新话题时清理先前普通历史；下一次接话单列不可信观察，跳过旧记忆召回，回应主人最新消息。临时数据不进入system；system只添加固定解释。
- 一次普通回复确认/部分确认或送达未知后即释放观察，失败时可在有效期内继续；人格/lease/会话失效、明确换话题或个人回忆请求、过期/时钟回退均不可复用。设置和作用域切换继续执行既有失效逻辑。显式“请记住”仍走真实主人保存接口。
- 接话携带 `external` 排除标记到Rust确认边界，因此引用分享的回答也不作为主人事实整理。`searchRequested`单独表示本轮搜索，避免把临时观察错误描述为本轮搜索成功/搜索未配置。
- 新主人输入可能先于ACK到达：等待既有有界送达收尾，只对确认前缀恢复观察，绝不带入未送出的余段。超过既有2.5秒等待边界的回执不保证赶上本轮生成，不延长网络等待或自动重发。
