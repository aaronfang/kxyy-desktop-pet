# 大模型技术消息检索漏搜与资料缩水

本轮问题：“有没有大模型相关的消息？偏技术向的”，角色回答没有搜到靠谱消息。目标是确认检索是否发生、搜索词是否保留技术方向、结果是否被丢弃、最终模型是否实际得到资料。仅本地修改，不提交／推送。

## 已复现的事实

1. 使用原话经当前 QQ 控制器和真实开发版代理复测三轮，均能检索并生成带来源回答；其中一轮 Tavily 6001ms 超时后，DeepSeek 448ms 返回4条。没有复现“供应商一条也没有”，也没有该用户原轮次的完整阶段记录，不能百分之百还原那次失败。
2. 对原话连续做10次真实语义判断，其中一次2517ms超时，得到空计划，**未向任何搜索服务请求**；其他9次573—1440ms给出搜索计划。这是一个实际复现的漏搜路径，不是稳定故障率统计。原兜底要求“最近／最新”等词，原话只有“消息、偏技术”，漏掉该情形。后续人格在没有资料时仍能说“没搜到靠谱消息”，造成用户误以为实际搜索过。
3. 查询规划返回“大模型 技术进展 2026年10月”，自行加了用户没要求的年月，且不足以保留“偏技术”的范围。直接比较三个公开查询、两家服务共6次请求，全部HTTP200／4条。旧查询有部分摘要混入融资等信息；增加技术方向关键词的中文查询在本次样本中全部包含技术相关词且未匹配财经词。此处只是有限关键词统计，不是人工来源质量评级或所有查询效果保证。
4. 公开过滤器虽然上轮放行token等词，但仍无条件拒绝“system prompt”“tool call”“系统提示词”“调用工具”。真实技术描述在原生、JS测试中均被复现为零条。这是确定的可触发缺陷，但本次6次真实供应商样本未遇到这些拒绝词，不能声称它解释了用户原轮次。
5. JS原本先按1800字摘要预算接受最多3条600字资料，渲染时又将标题、链接等算入1800字预算并直接break，后面已接受来源静默丢失。此前实测只断言“资料块存在”，没有保证每条来源到达最终模型，这个验收不足。600字×4的回归测试旧实现只能接受3条；后续完整块渲染还会进一步缩水。

## 修正

- 公开AI／大模型等资讯自然提问在语义判断失败、超时或错误否决时仍有搜索兜底，不要求用户添加“最近”“查一下”等触发词；明确不联网、私人消息与记忆请求继续跳过。没有执行检索时，应用明确禁止角色声称搜过或没搜到。
- 查询规划保留技术方向；宽泛资讯问题不擅自加入年月日硬约束。对该类问题的模型计划再做本地校验，剔除用户没要求的数字年月日；用户明确提出的日期仍保留。天气日期换算保持原合同。不额外增加搜索请求或后台搜索。
- 公共技术词汇以不可信数据保留；继续拦截真实凭据、明确覆盖规则／泄露系统提示词／执行工具的指令。私人Memory过滤保持不变；资料仍不能改变系统／工具权限，仍不进入长期Memory。
- 一份最终1800字符预算同时容纳标题、链接、时间与摘要，先为来源保留空间再分配摘要长度；通常可完整保留4个来源。长元数据、短摘要、异常来源仍受边界约束。提示词明确抓取时间不是发布时间，有部分相关资料时报告具体内容与不足，不能一概声称没有资料。

## 当前能力与未验收范围

现在仍是“一个有界查询＋最多4条搜索摘要＋一次角色回答”，并非会逐篇阅读原文、核对发布日期、去重排名、比较一手论文或自动扩展检索的研究Agent。以上修复解决漏搜和确定的资料丢失，不能将摘要可用等同于技术资讯质量评估已完成。更深入的技术资讯能力需要独立设计多样化选题、来源质量和有限二次检索，保留有界等待和隐私合同。

本轮实际网络测试在macOS开发版代理进行，真实QQ控制器在VM运行，最后发送回执被替代；真人QQ收发与语音听感、Windows和安装包未重验。未修改电话搜索协议或QQ发送生命周期。开发版已由现有Tauri watcher重建并运行。
