# 实时语音测试版设备验收清单

状态：待人工执行。本文是发布测试版前的操作记录模板；自动化测试通过不等于麦克风、AEC、音质或真人等待感已通过。

## 0. 测试边界

每次测试记录：版本号、平台、设备型号、系统版本、音频输出方式（内置扬声器/耳机）、实时后端、文字 provider、模型设置、网络状态和时间。只记录计时、固定状态枚举、计数和主观评分，不复制完整 ASR、回复、网页正文、Memory 或密钥。

自动化基线先执行：

```text
npm test
npm run test:python
cargo test --offline --manifest-path src-tauri/Cargo.toml --lib
```

硬件测试至少覆盖一台 macOS 和一台 Windows 设备；若测试版只发布一个平台，仍需在该平台上完成全部项目。

## 1. 鲜话题缓存

前置：打开设置中的网页观察，完成一次应用重启；分别准备有网、断网和受限网络三种状态。启动预取不应阻塞窗口显示、语音服务启动或模型预热。

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 启动预取 | 启动应用后观察状态事件/设置状态 | 约 8 秒后出现成功、部分成功或失败的固定状态；UI 可用，旧缓存不被清空 |
| 电影 | 文字输入“最近有什么好看的电影” | 命中 `movies` 线索时有来源和发布时间；不命中时自然说明暂无可靠线索，不编造 |
| 游戏 | 文字输入“最近有什么游戏新闻” | 命中 `games`；最多 3 条，短摘录有界，不逐条播报 |
| 科技 | 文字输入“今天科技圈有什么有意思的事” | 命中 `technology`；抓取时间不冒充发布时间 |
| 实时共用 | 在上述文字查询后立即开始本地/CosyVoice 通话 | 通话开场或 final-ASR 后可消费同一缓存；只在 `fresh-topic-v1` 协商后出现 |
| 过期 | 将测试缓存的 `fetchedAt` 调到 7 天以上，重启并查询 | 过期条目不返回；若刷新失败，保留仍未过期的旧条目 |
| 离线 | 断网后查询已有缓存 | 未过期缓存仍可用；没有缓存时固定失败/空结果，不编造“最新消息” |
| 来源状态 | 打开设置页并点击“刷新状态” | 列出 15 个默认来源的分类、状态、候选/入选数量与最近时间，不展示正文；Steam 热门、机核和下厨房不应出现在默认来源列表 |
| 偏好配额 | 分别设置中立、感兴趣、不主动聊后重新采集 | 去重后分别最多保留 10、15、0 条；未启用分类不发起对应来源请求 |
| 手动刷新 | 连续点击“重新采集” | 首次执行采集，同来源 30 秒内不重复请求；失败保留同分类旧缓存，不用 HN/GDELT 跨类填充 |
| Tavily 无 Key/错 Key/超时 | 仅在设置显式选择 Tavily 时测试 | 失败保持免费来源或旧缓存；不把 Key、URL 或错误正文展示给模型/诊断 |
| 隔离 | 使用 Volcano 或未升级旧本地服务 | 不发送或使用 `freshTopics`，通话照常工作 |

验收记录至少包含：缓存命中率、查询耗时、预取耗时、每次返回条数/字符数，以及命中路径相对无缓存基线的 p50/p95。缓存命中路径相对基线不得增加超过 500ms。

## 2. DeepSeek 实时导演

前置：`textProvider=deepseek`、有效 DeepSeek Key、实时后端选择本地或 CosyVoice；再用同一设备切换 `textProvider=local` 和 Qwen3 做对照。每个 provider 完成三轮，每轮先说一个具体个人内容，再用短句回应元元。

每轮观察：

- 首轮有具体贡献，不以泛泛“你呢”结束。
- `expand -> offer-entry -> deepen` 有轮换，最多一个明确问题，不连续盘问。
- “你怎么看”“我也不知道，你觉得怎么办”等软意图只改变当前轮姿态，不改变长期偏好。
- 思考字段/推理内容不进入气泡、语音或诊断；DeepSeek SSE 错误后可继续说话重试。
- 本地 Qwen3 与 DeepSeek 的同一轮输入表现出相同的导演约束，只允许内容风格因模型而异。

故障回放：缺 Key、断网、代理超时各一次。通过条件是固定可理解的错误、通话不崩溃、挂断后资源回收，且不回退为伪造的当前信息。

## 3. 自动话题偏好

在文字聊天和实时通话各执行一次：

1. 说“我很喜欢电影，之后可以多聊这个”，确认出现 `inferred/interested` 候选。
2. 说“我不想主动聊工作”，确认出现 `inferred/not-interested` 候选。
3. 说“这个先不用记，还是中立吧”，在设置中改为 `neutral`。
4. 手动把同一类别设为喜欢，再重复前两句；手动项不得被覆盖。
5. 删除候选后重复普通沉默/“嗯”；不得再次生成偏好。

只接受明确表达；一次沉默、短回应或模型猜测不能生成长期候选。会后在设置中编辑、删除和恢复中立必须立即生效。

## 4. 音频与对话节奏

### 4.1 三轮基本通话

本地 Qwen3、CosyVoice、DeepSeek 各至少一轮三回合。记录：

- LLM 首 token、TTS 请求、首个下行音频、实际首个可听样本的时间戳。
- TTFA p50/p95、每轮等待主观评分（1 至 5）、音量和音质异常次数。
- 对含至少两段稳定句的长回复，记录 schema v9 `segmentContinuity.audibleGapMs` 的 count/p50/p95，并与听感中的第二句停顿逐轮对照。
- 元元主动续说等待是否从最终播放回执开始；三次未回应后保持安静。

### 4.2 AEC、插话与恢复

分别使用内置扬声器、耳机和距离扬声器约 1 米的环境：

- 元元播报时保持安静 2 分钟，记录误候选数和误确认数。
- 元元播报中说“打断一下”及一段完整内容，确认 duck/暂停、确认后丢弃未播尾段，并立即进入新一轮。
- 在候选窗口只发出短咳/环境声，确认被拒绝后原句继续播放，不出现音频突发或重复。
- 用户说“先听我说”“换个话题”“继续”各一次，确认固定控制生效。
- 麦克风权限拒绝、AudioContext 被挂起、输出设备切换各一次；状态可恢复且不会重复创建会话。

通过条件：无持续回声、无连续误打断；拒绝候选不会改变 audible history，确认打断不会把未播文本写入历史或 Memory。

### 4.3 真实语音思考填充

使用可产生明显思考延迟的本地 Qwen3 和 DeepSeek：

- 每个 provider 连续触发 5 轮较复杂问题，确认 LLM 请求 5 秒内有正文时只显示“思考中”，不播放 filler。
- 让测试桩超过 5 秒不输出正文，确认一轮最多一次“嗯，让我想想……”；正文开始后不得插入或重复 filler。
- 用户在 filler 播放期间开口，确认立即 duck/停止并让路，不把 filler 计入 audible history、recap、Memory 或诊断。
- TTS slot 忙、模型快速返回、服务不支持时确认静默降级，不阻塞正文 TTFA。

## 5. 通过门槛与交付物

以下任一项失败，测试版标记为“待修复”而非体验通过：

- 出现密钥、完整网页正文、完整会话文本或 PCM 泄漏到日志/诊断。
- 缓存过期后仍声称“最新”，或网络失败时编造事实。
- DeepSeek 不能恢复、导演提示绕过 provider 统一路径、或推理内容被播报。
- AEC 造成持续自激、确认/拒绝打断状态错误、音频顺序或速度明显异常。
- filler 超过一轮、正文 admission 后插入、用户开口后仍继续播放，或 filler 污染历史。

交付物：一份每设备一页的计时/主观评分表、脱敏 `diagnosticSchemaVersion:11`（如开启调试，其中 `runtime.captureProcessing` 记录浏览器音轨实际报告的 AEC、noise suppression 和 AGC 固定状态）、缓存 provider 状态截图/固定事件、失败步骤和复现条件。当前仓库只完成自动化与实现，真实设备项目在人工执行前保持“待验收”。
